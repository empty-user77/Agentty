---
title: 内置浏览器
description: 终端旁的浏览器面板、会自己打开的开发服务器，以及让智能体操作页面。
---

**⇧⌘B** 在终端旁打开浏览器面板。在 macOS 上它是 Agentty 内的 WebKit 视图，在 Windows 上是 Microsoft Edge WebView2（Chromium）视图；在 Linux 上则改为在你的默认浏览器中打开。Windows 10 和 11 自带 WebView2，未安装的电脑在打开浏览器时会提示从 Microsoft 下载并安装。

## 如何打开

- 在任意终端中 ⌘-点击链接（Windows 和 Linux 为 Ctrl-点击）。
- **设置 → 常规**决定 ⌘-点击使用内置浏览器还是默认浏览器。
- 输入网址，或输入搜索词 —— 搜索引擎可配置。

## 开发服务器

在标签页中启动的本地服务器会以 `:端口` 标签出现在工作区列表中，一旦返回页面就会在面板里打开。

关闭启动该服务器的标签页会一并停止服务器。两种行为都可以在**设置 → 常规**和**设置 → 浏览器**中关闭。

## 响应式模式

地址栏旁的手机按钮会按设备尺寸而非面板尺寸排布页面：iPhone SE, iPhone 15 Pro, iPhone 15 Pro Max, Pixel 8, Galaxy S24, iPad mini, iPad Air, iPad Pro 12.9", Laptop, Desktop，也可以直接输入任意宽度和高度。页面会居中并缩放以适应面板剩余的空间，因此 1920 宽的桌面布局在窄面板里也看得清。旋转会交换这两个数值，拖动右边或下边的边缘则可手动调整大小。

关闭后，页面回到面板本身的宽度。

## 使用 Chrome 的登录信息登录

在 macOS 上,页面要求登录时,页面上方的栏会询问是否使用 Google Chrome 中已有的登录信息。选择**以后总是**后会自动查找,**仅这一次**只用这一次,**不用**则在 Agentty 重启前不再询问该网站。第一次使用时,macOS 会询问是否允许 Agentty 使用 Chrome 的存储密钥,请选择**允许**。

- **成功时**,页面会以已登录状态重新加载,栏中会显示信息来自哪个 Chrome 配置文件。
- **Chrome 的信息无法登录时**,页面会被模糊遮盖,在 Chrome 中完成验证后,通常一分钟内会自动同步。选择**直接验证**可回到页面并在此登录,选择**在 Chrome 中打开**可在 Chrome 中打开该页面。
- **在这里退出登录后**,30 分钟内不会自动重新读取,而是先在栏中询问。

可在**设置 → 浏览器 → 登录**中选择询问、总是或关闭,并在有多个配置文件时选择要使用的 Chrome 配置文件。未选择时先尝试最近使用的配置文件,无法登录再尝试下一个。

只复制浏览器会发送给该网站的 Cookie,并放入应用内浏览器(若按终端分开,则放入该终端的 Cookie)。插件页面和隐私模式下不会读取。智能体无法代为回答,也无法指定网站,只能通过 `browser_status` 的 `signIn` 查看进度。但设为**总是**时,无论谁打开,登录页面本身就足够:智能体打开登录页面时,如果 Chrome 已登录该网站,即使在你没看的标签页中也会直接进入,并在该会话中操作。如需每次自己决定,请设为**询问**。

有些网站把登录绑定到创建它的浏览器并拒绝副本,这时请在这里登录一次。Windows 上不可用:那里的 Chrome 把密钥绑定在 Chrome 本身。

## 让智能体操作它

Claude Code 和 Codex 可以通过 MCP 控制这个浏览器：点击、输入、读取控制台、截图。这是智能体在运行中的页面上检查自己工作的方式。

智能体拿到的工具如下：

| 工具 | 作用 |
|---|---|
| `browser_open` | 打开此终端的标签页（首次会新建），可选地加载一个 URL |
| `browser_navigate` | 加载 URL、`主机:端口` 或搜索词 |
| `browser_status` | 当前 URL、标题，以及是否仍在加载 |
| `browser_wait_load` | 等待加载完成 |
| `browser_click` | 点击元素 |
| `browser_console` | 读取页面的控制台输出 |
| `browser_screenshot` | 截取页面 |
| `browser_viewport` | 按设备尺寸、`WxH` 或 `off` 排布页面 |
| `browser_close` | 关闭此终端的标签页 |

它们在 Agentty 启动智能体时一并注册，无需安装或配置。典型的流程是：智能体启动开发服务器、打开页面、点击自己刚做的改动、从控制台读取错误，然后修掉发现的问题。

### 每个终端一个浏览器

每个终端都有自己的浏览器。在一个终端里打开浏览器访问某个网站，在另一个终端里打开浏览器访问另一个网站，每次选择终端时，都会看到该终端的浏览器，保持离开时的样子；从未打开过浏览器的终端，面板是关闭的。不在前台的终端里的页面仍会继续加载、运行脚本、截图，工作不会因为你没在看而停下。

- **链接和服务器归属各自的终端。** 在终端里点击的链接、该终端启动的服务器的端口标签、自动打开的服务器页面，都会在该终端的浏览器里打开。点击其他工作区卡片上的端口标签，会选中那个终端。
- **智能体在其终端浏览器中自己的标签页里工作。** 首次 `browser_open` 时创建，以终端的文件夹和编号（`app #3`）标示。该智能体的所有操作只作用于这个标签页，不会改动其他终端的页面、你打开的页面或插件的页面。页面无论是否显示都按 1280px（或用 `browser_viewport` 设定的尺寸）布局，显示时缩放以适应面板，结果不受面板宽度影响。
- **用上限保持轻量。** 在后台运行的终端浏览器最多 6 个，所有应用内浏览器页面合计使用的内存最多为本机内存的 30%（均在 **设置 → 浏览器** 中）。超过任一上限时，从最久未看的开始卸载后台浏览器；屏幕上的浏览器以及智能体在最近两分钟内发送过命令的浏览器不会被卸载。被卸载的页面会记住地址，在选中该终端或其智能体发送命令时重新加载（此时命令会在加载完成后执行）。
- **关闭面板会隐藏该终端的浏览器**，再次打开时原样恢复。**关闭终端时，它的浏览器也会关闭。**
- **Cookie 和登录状态是共享的**，网站只需登录一次。若要让每个智能体标签页使用独立的 Cookie，请打开 **设置 → 浏览器 → 每个终端使用独立的 Cookie 和登录状态**（macOS 14 及以上；Windows 需 WebView2 运行时 101 及以上）；终端关闭时一并清除。

> [!IMPORTANT]
> 这个浏览器保留着你已登录的会话。智能体操作它时就是在这些会话中行动。需要时再启用，并留意哪些标签页是开着的。
