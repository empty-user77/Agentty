title: 内置浏览器
description: 终端旁的浏览器面板、会自己打开的开发服务器，以及让智能体操作页面。
---

**⇧⌘B** 在终端旁打开浏览器面板。在 macOS 上它是 Agentty 内的 WebKit 视图；在 Windows 和 Linux 上则改为在你的默认浏览器中打开。

## 如何打开

- 在任意终端中 ⌘-点击链接（Windows 和 Linux 为 Ctrl-点击）。
- **设置 → 常规**决定 ⌘-点击使用内置浏览器还是默认浏览器。
- 输入网址，或输入搜索词 —— 搜索引擎可配置。

## 开发服务器

在标签页中启动的本地服务器会以 `:端口` 标签出现在工作区列表中，一旦返回页面就会在面板里打开。

关闭启动该服务器的标签页会一并停止服务器。两种行为都可以在**设置 → 常规**和**设置 → 浏览器**中关闭。

## 响应式模式

地址栏旁的手机按钮会按设备尺寸而非面板尺寸排布页面：iPhone SE, iPhone 15 Pro, iPhone 15 Pro Max, Pixel 8, Galaxy S24, iPad mini, iPad Air, iPad Pro 12.9", Laptop, Desktop，也可以直接输入任意宽度和高度。页面会居中并缩放以适应面板剩余的空间，因此 1920 宽的桌面布局在窄面板里也看得清。旋转会交换这两个数值，拖动右边或下边的边缘则可手动调整大小。

关闭后，页面回到面板本身的宽度。

## 让智能体操作它

Claude Code 和 Codex 可以通过 MCP 控制这个浏览器：点击、输入、读取控制台、截图。这是智能体在运行中的页面上检查自己工作的方式。

智能体拿到的工具如下：

| 工具 | 作用 |
|---|---|
| `browser_open` | 打开此终端的标签页（首次会新建），可选地加载一个 URL |
| `browser_navigate` | 加载 URL、`主机:端口` 或搜索词 |
| `browser_status` | 当前 URL、标题，以及是否仍在加载 |
| `browser_wait_load` | 等待加载完成 |
| `browser_click` | 点击元素 |
| `browser_console` | 读取页面的控制台输出 |
| `browser_screenshot` | 截取页面 |
| `browser_viewport` | 按设备尺寸、`WxH` 或 `off` 排布页面 |
| `browser_close` | 关闭此终端的标签页 |

它们在 Agentty 启动智能体时一并注册，无需安装或配置。典型的流程是：智能体启动开发服务器、打开页面、点击自己刚做的改动、从控制台读取错误，然后修掉发现的问题。

### 每个终端一个标签页

智能体首次打开页面时，会得到该终端专用的浏览器标签页，以终端的文件夹和编号（`app #3`）标示。该智能体的所有操作只作用于这个标签页，不会改动其他终端的页面、你自己打开的标签页或插件的页面。因此多个终端里的智能体可以同时测试不同的应用。

- **选择某个终端时，它的标签页会切到前面。** 你没在看的终端里的智能体不会改变屏幕内容，它的标签页会加在后面。
- **不在前面也照常工作。** 不在前面的标签页照样加载、运行脚本、截图。页面无论是否显示都按 1280px（或用 `browser_viewport` 设定的尺寸）布局，显示时缩放以适应面板，所以智能体检查的结果不受面板宽度影响。每个标签页各自保留响应式尺寸。
- **关闭终端时，它的标签页也会关闭。**
- **Cookie 和登录状态由所有标签页共享**，网站只需登录一次。若要让每个终端使用独立的 Cookie，请打开 **设置 → 浏览器 → 每个终端使用独立的 Cookie 和登录状态**（macOS 14 及以上）；终端关闭时一并清除。

> [!IMPORTANT]
> 这个浏览器保留着你已登录的会话。智能体操作它时就是在这些会话中行动。需要时再启用，并留意哪些标签页是开着的。
