---
title: 从想法开始
description: 把几句话和几个附件变成智能体可以立刻动工的项目文件夹。
---

“从想法开始”面向项目还不存在的阶段。你用一段简短的对话描述想要什么、附上手头的材料，Agentty 就会创建一个供智能体出发的文件夹。

可以从起始页、**+** 菜单或命令面板打开。不需要这个提议的话，可在**设置 → 常规**中关闭。

## 会创建什么

一个新文件夹（默认在 `~/AgenttyProjects` 下），包含：

| 路径 | 内容 |
|---|---|
| `docs/idea/IDEA.md` | 你写下的内容，按顺序 |
| `docs/idea/attachments/` | 你附上的文件副本 |
| `docs/idea/BUILD_GUIDE.md` | 工作方式：先规划、再构建，并实时预览 |
| `.claude/settings.json` | 让智能体不必为每条命令询问就能安装依赖、运行开发服务器的权限 |

其余一律留空，这样 `create-next-app`、`create vite` 等脚手架工具仍会接受这个文件夹。

附件上限为 20 个，每个 20 MB。

## 然后呢

Agentty 会在那个文件夹里打开一个智能体，并把第一条提示词准备好。你可以在[内置浏览器](/docs/in-app-browser)里看着结果成形。**开发方式**决定由谁来构建：

- **智能体团队**（由 Claude Code 或 Codex 构建且设置中开启了编排时的默认）：智能体主导一次[编排](/docs/session-flow)。团队从想法到代码一步一步推进，每个阶段都在 `docs/design/` 中为下一阶段留下文档：
  1. 想法分析：问题、用户、替代方案、风险，以及所做的假设
  2. 想法推导：价值、功能优先级、演示范围
  3. PRD：带验收标准的用户故事、页面和流程
  4. HLD（概要设计）：技术栈、架构、数据模型、页面
  5. LLD（详细设计）：文件、组件和接口，以及拆分成构建单元的工作
  6. 团队组建：项目的 harness，每个构建单元一名开发者
  7. 开发：先搭基础，构建单元并行，最后在浏览器中检查质量并对照 PRD 审查

  同一阶段内有多个智能体并行工作（例如分析阶段的用户、市场和可行性），阶段之间按顺序交接。它们在编排页面上以波次显示。
- **单个智能体**：由一个智能体独自规划并构建。

准备好上线时，交给 [Launch](/docs/launch) 发布。
