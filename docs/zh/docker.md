在带有 compose 文件、Dockerfile 或自有容器的项目中，状态栏会显示该项目有多少容器在运行（🐳 3 running）。点击即可打开面板。

Agentty 在项目根目录查找 `compose.yaml`、`compose.yml`、`docker-compose.yml` 和 `docker-compose.yaml` —— 与 `docker compose` 自己使用的名称和顺序一致。没有 compose 文件时，则列出该项目自己的容器。

面板跟随活动窗格的工作树，所以切到另一个项目的窗格时，看到的容器也会随之改变。

## 面板显示什么

每个 compose 服务或容器的镜像、状态（运行中、已停止、不健康）和端口。

## 可以做什么

| 操作 | 说明 |
|---|---|
| 启动 / 停止 / 重启服务 | |
| `compose up -d` | 可能先拉取镜像，所以允许多花些时间 |
| `compose down` | **会确认两次。** 卷会保留 |
| 日志 | 在新标签页中打开，便于一边工作一边查看 |

## 刻意不读取的内容

**绝不读取或显示环境变量的值。** compose 文件及其旁边的 `.env` 常常存着数据库密码，而 `docker compose config` 会把它们完全解析后打印出来。Agentty 只读取名称、镜像、状态和端口。

每一条 Docker 命令都以参数数组执行，从不经过 shell；服务或容器名只有在 Docker 自己报告过、并通过有效性检查之后才会被传入命令。compose 文件里一个畸形的名称不会变成命令。

## 如果面板是空的

- Docker 守护进程可能还在启动 —— 列表查询有 15 秒超时，慢启动的守护进程不会冻住面板。
- 确认项目根目录确实有上述四个 compose 文件名之一，或存在标记为该项目的容器。
