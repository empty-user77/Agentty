---
title: 智能体状态
description: Agentty 如何得知每个智能体在做什么，又如何告诉你。
---

Agentty 会盯着你启动的智能体，逐个显示它是在工作、已完成，还是在等你。

## 状态出现在哪里

- **侧边栏** —— 每个工作区行承载其中智能体的状态。
- **窗格边框** —— 当智能体提问或请求权限时亮起，直到你点击该窗格。
- **智能体窗格上方的状态栏** —— 模型、上下文窗口、用量限额、分支、文件夹。
- **通知** —— 智能体完成或需要回答时。点击即可打开该窗格。
- **⇧⌘U** —— 跳转到最新的未读窗格。
- **迷你模式与菜单栏** —— 不用把窗口放在前面也能掌握状态。

## 上下文窗口

状态栏里的上下文数值是一个计量条：点击它会打开**上下文记忆**面板，将窗口拆分为系统与工具、记忆文件、技能、摘要和对话，并列出自上次压缩以来读取或编辑过的文件。

窗口大小采用代理自己报告的值（Claude Code 通过状态栏，Codex 通过会话日志），从不根据模型名称猜测。在报告之前，计量条只显示已用的 token 数，不显示百分比。

面板中该数值旁边有一个**压缩**按钮。无论数值是多少，它都会运行智能体自己的压缩命令（Claude Code、Codex），让你在开始一段长任务之前腾出空间，而不是之后。状态栏自身的压缩按钮从 70% 开始出现——也就是计量条转为橙色的那一刻。

## 状态种类

| 状态 | 含义 |
|---|---|
| 工作中 | 正在运行工具 |
| 思考中 | 一轮进行中，处于工具调用之间 |
| 等待输入 | 提出了问题或请求权限 |
| 已完成 | 本轮结束 |
| 空闲 | 没有正在运行的东西 |

## 工作原理

Agentty 在启动窗格时通过命令行传给智能体一个状态钩子。智能体把状态报告到一个只有你的用户账号能访问的本地套接字。不会向你的项目或智能体自身的配置文件里写入任何内容。

## 通知

在**设置 → 通知**中设定：

- 智能体完成或需要输入时的系统通知。
- Agentty 处于前台时是否也通知。
- 提问和权限请求始终通知，除非你正看着那个窗格。
- 智能体即使多次上报同一个提问，一个提问也只产生一条通知。你回答之后的新提问会再次通知。

### 在通知中直接允许或拒绝

Claude Code 或 Codex 的权限请求通知会显示请求内容（工具，若是命令则显示其内容），并带有**允许**和**拒绝**按钮。macOS 通知和迷你窗口的气泡都一样。允许会以“Yes”放行一次；拒绝以“No”（Esc）回答，智能体会等待你的其他指示。两者都不会把 Agentty 调到前台。“以后不再询问”只能在终端中选择。

只有当该请求仍在屏幕上等待时，Agentty 才会输入答案。如果你已经在终端中回答，或智能体已继续下一步，按钮不会输入，而是打开那个窗格。在 macOS 上，允许需要 Mac 处于解锁状态。横幅样式下，指针悬停在通知上时才显示按钮；在系统设置 → 通知中把 Agentty 设为**提醒**样式即可一直显示。需要从多个答案中选择的提问请在终端中回答。
- “在前台”是指当下 Agentty 是否为活动应用。

### 发到手机

同一页面可以连接 **Slack**、**Discord** 或 **Telegram**，这样你离开机器时问题也能找到你。你可以选择只在智能体需要你时发送，还是完成时也发送，以及是否包含智能体问了什么。

Slack 和 Discord 两种方式都可以：使用 Webhook 地址，或者用机器人令牌加上要写入的频道 —— Slack 接受 `#general`、`general` 或频道 id，Discord 用频道 id。Telegram 始终是机器人，需指定要写入的对话。

Webhook 地址和机器人令牌保存在操作系统的凭据存储中，而不是设置文件里。
