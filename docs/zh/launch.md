---
title: Launch 发布
description: 把电脑上的一个文件夹变成线上的 URL —— GitHub、Vercel，需要时还有 Supabase。
---

Launch 是随附的发布插件：**GitHub 登录 → 保存到仓库 → Vercel 登录 → 项目用到时配置数据库 → 环境变量 → 发布**。一次一步，一个主按钮，不用手工复制令牌。

从窗格上方的火箭按钮，或命令面板（**Launch: Publish this project to the web**）打开。

## 各个步骤

1. **项目检查** —— 查看活动窗格的文件夹，识别框架（Next.js、Vite、Astro、静态站点等）。
2. **工具** —— 需要 GitHub CLI 和 Vercel CLI。若 `PATH` 中都没有，Launch 会把它们装进自己的数据文件夹 —— 不做任何系统级安装。
3. **GitHub 登录** —— 如果 GitHub CLI 已登录，或这台电脑有可以推送到该仓库的 SSH 密钥，就跳过。否则替你运行 CLI 的浏览器登录，一次性代码会大字显示并复制到剪贴板。只有需要新建仓库时才会要求登录。
4. **保存到 GitHub** —— 提交全部内容并创建一个新的私有仓库。公开与否是一个开关。
5. **Vercel 登录** —— 同样的流程。
6. **数据库** —— 仅当项目使用 Supabase，或你点击了**连接数据库**时才进行。
7. **环境变量** —— 若存在 `.env` 文件，只列出其中变量的**名称**（绝不显示值），每个都带一个开关。只在本机有意义的值默认关闭。
8. **发布** —— 部署到生产环境并实时显示日志，然后把仓库接到 Vercel，使之后的 push 自动部署。

## 当文件夹不是 Web 项目时

Launch 会改为打开一个 **仪表盘**：已安装的命令行工具、GitHub 和 Vercel 的登录状态，以及 Vercel 账户中的所有项目和各自部署来源的仓库。在还没有要发布的内容之前，就可以在这里完成两项登录。仪表盘和发布步骤通过标签切换，你正在看的终端所在的文件夹决定打开哪一个。

## 它刻意不做的事

- 在首次提交前把 env 文件、密钥文件和本地工具状态加入 `.gitignore`，并且**如果真实的 env 文件或密钥文件已被跟踪或暂存，就拒绝保存**。
- 已有远程仓库的项目会先显示它指向哪里，并在推送前询问一次。
- 会先写 `.vercelignore`，所以想法笔记、`.claude/`、迁移脚本和 env 文件都不会被上传。

## 用谁的账号

你自己的。Launch 通过各服务的官方工具和它们自己的登录页面为你登录，令牌由那些工具保存在你的机器上。你发布的内容按各公司的条款送往 GitHub、Vercel 和 Supabase，其中没有任何内容到达我们这里。

任何失败的步骤都会显示一条简短信息，并给出**重试**以及把问题交给智能体处理的选项。
