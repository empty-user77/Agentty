Agentty 是为运行 AI 编程智能体的人准备的终端。它做终端该做的事（shell、标签页、分屏、回滚缓冲），并加上第二个智能体开始工作的那一刻你就会需要的东西：每个项目的位置、每个智能体的状态、查看它们改了什么的方式，以及有谁在等你时的提醒。

它是用 Rust 编写、由 GPU 渲染的原生应用。没有 Electron，没有包住终端的网页视图，也没有需要注册的账号。

## 它解决什么问题

运行一个智能体很简单：在终端里执行 `claude` 然后盯着看就行。到了五个，终端就帮不上忙了。标签页长得一模一样，你会搞不清哪个在等回答，两个智能体会改同一个文件，而花了多少钱要等账单来了才知道。

Agentty 正是为后一种情形而造。

- **你永远知道谁在等你。** 每个工作区都会显示其智能体是在工作、已完成，还是在等待输入。需要回答时窗格边框会亮起，你人不在时会收到通知。
- **智能体之间不会互相干扰。** 同一项目中的第二个会话会在自己的 git 工作树和独立分支上启动，两个智能体不会改到同一批文件。
- **工作内容一目了然。** 类似 GitHub Desktop 的 git 页面、显示所有工作树的文件面板，以及由本机会话记录生成的用量看板。

## 核心概念

### 工作区 → 标签页 → 分屏

**工作区**就是一个项目：一个文件夹、侧边栏中的一行，以及你为它打开的一切。工作区里有**标签页**，标签页可以**分屏**成多个窗格。窗格可以是 shell、AI 智能体、文件编辑器或浏览器。

工作区可以分组和重新排序，重启之后会保持你离开时的样子。

### 窗格运行的是真正的程序

智能体窗格运行的是真正的命令行工具：`claude`、`codex`，或你安装的其他智能体，跑在真实的 PTY 上。Agentty 只是传给它一个用于汇报状态的钩子，并读取它本来就会写下的会话文件。它不中转对话，不改写你的配置文件，也不插在智能体与其提供方之间。

正因如此，智能体在 Agentty 里的表现与在你自己的终端里完全一致，升级智能体 CLI 也不必等待 Agentty 发版。

### 一切都在本地

Agentty 没有后端。会话列表、搜索、用量数字、费用估算和上下文文档，全都由你自己电脑上的文件生成。你的对话、代码和凭据不会经过我们的服务器——因为根本不存在这样的服务器。

你交给 Agentty 的密钥会存进操作系统的凭据存储：macOS 用钥匙串，Windows 用凭据管理器，Linux 用 Secret Service。

> [!NOTE]
> 你运行的智能体 CLI 会与各自的提供方通信：Claude Code 连 Anthropic，Codex 连 OpenAI，用你自己的账号从你的电脑直接通信，与在任何其他终端中运行完全相同。Agentty 不站在中间，既不中转也不接收，这些通信受各提供方自己的条款和隐私政策约束。Agentty 自身发送的内容整理在[使用统计](/docs/telemetry)中。

## 提供的功能

| 领域 | 内容 |
|---|---|
| **智能体状态** | 每个工作区的实时状态、等待回答的窗格边框提示、通知与通知中心、跳转到最新未读 |
| **会话** | 浏览并恢复 `~/.claude` 与 `~/.codex` 的会话，按标题或内容搜索，在 Claude 与 Codex 之间迁移对话 |
| **Session Flow** | 从一个智能体拉一条线到另一个以共享上下文；标为实时后每一轮都会自动转发 |
| **Git** | 切换仓库与分支，fetch、pull、push，查看差异，只提交选中的文件，浏览历史，合并分支 |
| **工作树** | 每个会话一个工作树，面板显示所有工作树、谁在其中工作以及改了什么 |
| **文件与编辑器** | 项目树、带语法高亮与格式化工具的编辑器、用 VS Code 或 Cursor 打开 |
| **扩展** | Claude Code 与 Codex 的技能、子智能体、命令、插件和 MCP 服务器集中管理 |
| **监控** | 由本机会话记录计算的费用、令牌、缓存命中率与模型，运行中的 AI 进程，以及显示各标签页通信对象的抓取代理 |
| **插件** | 面板、按钮、命令面板条目，以及来自其他应用的 `agentty://` 链接 —— 参见[插件](/docs/plugins-overview) |

## 支持的平台

Agentty 面向 macOS、Windows 和 Linux 构建，macOS 是基准平台。三个平台都可以在发布页面下载。另外两个平台具备所有不依赖 AppKit 或 WebKit 的功能，差异整理在[平台](/docs/platforms)中。
