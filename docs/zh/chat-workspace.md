---
title: 聊天工作区
description: 在聊天中与一个主控智能体对话，同时在下方观看它分派工作的最多 4 个工作智能体和审查者。
---

聊天工作区上方是对话，下方是一组智能体。你在聊天中与一个 **主控智能体**（Claude Code）对话。它负责规划工作，把工作拆分交给 **工作智能体**，还可以让 **审查者** 检查它们的成果。每个智能体都在聊天下方网格中的独立终端里运行，你可以一次看到整个团队的进展。

## 打开方式

- 在开始页面（或 **新建工作区**）选择 **聊天 · 团队**，然后选择项目文件夹。
- 或在标签页旁的 **+** 菜单中选择 **新建聊天工作区**。

## 聊天的分支

在 git 仓库中，每个聊天都有自己的分支（`agentty/chat-…`，显示在聊天栏中），主控智能体在该分支的工作树中工作。你的项目文件夹不会被改动。

- 每个工作智能体都有自己的工作树，位于新分支上。这个分支从 **聊天分支的最新提交** 开始，所以主控智能体已经合并的工作，下一个工作智能体可以直接在其基础上继续。
- 主控智能体检查工作后，会把工作智能体的分支合并到聊天分支。
- 只有在你要求时，结果才会进入项目文件夹：仓库有远程时，主控智能体会创建拉取请求；没有远程时，会在项目文件夹没有未提交更改的情况下合并到该文件夹。

没有任何提交的仓库无处分出分支。此时主控智能体在项目文件夹中工作，在它完成第一次提交后，工作智能体从默认分支开始。

## 工作方式

1. 在聊天中输入。**Enter** 发送，**Shift+Enter** 换行。
2. 小事主控智能体自己处理。较大的工作，它会先制定计划，再用 `agentty tasks` 启动工作智能体。在聊天工作区中，它们会立即启动，不弹出通常的确认对话框：打开聊天即表示同意。
3. 工作智能体出现在聊天下方的网格中，每行两个，包括审查者在内同时最多 **4** 个。四个位置都占满时，最早完成的那个会关闭，为下一个腾出位置。它的分支和会话会保留，可以从会话列表中继续。
4. 工作智能体结束一个回合后，Agentty 会向主控智能体发送简短报告，包括工作智能体的标题、分支、文件夹和最后的回复。主控智能体检查工作后，会合并它、在聊天中告诉你结果，或者给该工作智能体发送后续指示。

聊天上方的栏显示主控智能体的状态、聊天分支，以及每个工作智能体的标签。点击标签即可跳到该工作智能体的终端。如果某个工作智能体在等你（审批或回答问题），聊天中也会提示。

## 工作智能体与审查者

聊天栏中的两个按钮决定由谁来工作：

| 按钮 | 选项 | 决定什么 |
|---|---|---|
| **工作智能体** | Claude · Codex | 主控智能体没有为任务指定时，新工作智能体使用的智能体 |
| **审查者** | 关闭 · Claude · Codex | 是否要求主控智能体在合并前审查每个工作智能体的成果，以及由哪个智能体审查 |

**审查者** 在工作智能体的文件夹中启动，对照聊天分支阅读其更改。它可以运行测试，并被要求不做任何更改：Codex 在只读沙箱中运行；Claude Code 没有编辑工具（但仍可通过 shell 写入，此时依赖于指示）。最后一行是 `Verdict: approve` 或 `Verdict: changes needed`，报告像工作智能体的报告一样交给主控智能体。即使审查关闭，主控智能体也可以启动审查者，此时仍使用按钮所选的智能体。

你的选择会随聊天一起保存。

## 主控智能体的终端

聊天是真实 Claude Code 会话的视图。点击栏上的 **终端** 显示主控智能体的终端，点击 **聊天** 返回。遇到只能在终端中回答的情况时，终端会自动出现：

- 首次运行时确认是否信任文件夹，或需要登录
- 主控智能体请求工具审批或提出问题

在终端中回答后会回到聊天。在此期间到达的消息会等主控智能体空闲时再交给它。智能体屏幕上显示审批或问题时，Agentty 不会向它输入任何内容。

## 主控智能体使用的命令

| 命令 | 作用 |
|---|---|
| `agentty tasks --plan <plan.json>` / `--title … --prompt-file …` | 启动工作智能体（这里不弹对话框） |
| `agentty tasks status` | 列出工作智能体、各自的状态以及聊天的选择 |
| `agentty tasks send --to <标题> --prompt <内容>` | 给工作智能体发送后续消息 |
| `agentty tasks result --to <标题>` | 再次显示工作智能体的最后回复 |
| `agentty tasks stop --to <标题>` | 关闭工作智能体（分支和会话保留） |
| `agentty tasks review --worker <标题> [--prompt <关注点>] [--agent claude\|codex]` | 为工作智能体的成果启动审查者 |

这些命令只有聊天工作区的主控智能体能用，且只能用于它自己的工作智能体。

## 须知

- 工作智能体在各自的分支上提交。只有在你向主控智能体提出要求时，才会推送或创建拉取请求。
- 每个工作智能体和审查者都是完整的智能体会话，四个同时工作会比一个更快消耗套餐额度。
- 拖动聊天与网格之间的分隔线，可以调整两者大小。布局会随工作区一起保存。
- 在设置中关闭 **智能体可启动并行任务**，聊天的主控智能体也将无法启动工作智能体。
- 在聊天分支功能推出之前打开的聊天，仍在项目文件夹中工作。
