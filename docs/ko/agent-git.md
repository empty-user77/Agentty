## git 페이지

**⇧⌘G**가 GitHub Desktop 형태의 페이지를 엽니다.

- 저장소와 브랜치 전환
- **fetch**(⇧⌘T), **pull**, **push**(⌘P), **새로 고침**(⌘R)
- 변경 사항을 파일별로 검토하고 원하는 것만 스테이지해 커밋(⌘↩)
- 히스토리 탐색과 브랜치 병합

Agentty는 이용자의 `git`을 설정과 자격 증명까지 그대로 씁니다. 모든 명령이 비대화형으로 실행되므로 보이지 않는 프롬프트에서 멈추는 일이 없습니다. 자격 증명 도우미가 처리하지 못하는 push는 멈춰 있지 않고 메시지를 띄우며 실패합니다.

## 페인에서 바로

어느 페인이든 헤더의 브랜치 이름을 클릭하면 터미널을 떠나지 않고 브랜치 전환, pull, push, 이름 복사를 할 수 있습니다.

목록의 브랜치를 우클릭하면 **이 브랜치로 전환**, **이름 바꾸기…**, **여기서 새 브랜치…**, **이름 복사**, **브랜치 삭제**를 쓸 수 있습니다. 어디에도 병합되지 않은 커밋이 있는 브랜치는 한 번 더 물은 뒤에만 삭제합니다. 다이얼로그에서 원격 사본도 함께 지울 수 있습니다(**원격 브랜치(…)도 함께 삭제**). **서버(원격)에서 삭제**는 확인을 거쳐 모든 사람에게서 원격 브랜치를 지웁니다. git은 한 브랜치를 한 번에 한 폴더에서만 열 수 있습니다. 그래서 다른 폴더가 그 브랜치를 쓰고 있어 전환이 거부되면 조용히 실패하지 않고 **그 폴더 열기**를 제안합니다.

### AI로 해결하기

병합이 충돌로 멈췄거나, 브랜치와 원격 브랜치가 갈라져 pull할 수 없거나, 해결되지 않은 충돌이 남아 있으면 메시지에 **AI로 해결하기**가 나타납니다. 누르면 저장소에서 Claude Code를(없으면 Codex나 설치된 다른 에이전트를) 열고 충돌 해결 지침을 전달합니다. 설치된 에이전트가 없으면 저장소에서 터미널만 엽니다. 병합이 진행 중일 때는 다른 병합을 시작하지 않습니다.

## 세션마다 하나의 워크트리

이미 다른 세션이 작업 중인 프로젝트에서 두 번째 AI 세션을 열면, Agentty가 어디서 시작할지 묻습니다. **새 워크트리 만들기**는 프로젝트 기본 브랜치에서 새 브랜치를 따고 그 브랜치의 전용 git 워크트리에서 시작합니다. 두 에이전트가 같은 파일을 고칠 일이 없습니다. **기존 워크트리 열기**는 같은 워크트리에서 새 세션만 시작합니다. 한 브랜치를 두 세션이 함께 보거나 작업할 때 쓰세요. 터미널에 `claude`나 `codex`를 직접 입력해도 같은 질문이 나옵니다.

- 워크트리는 `~/.agentty/worktrees/` 아래에, `agentty/<이름>` 브랜치로 만들어집니다.
- 모든 세션을 한 폴더에서 돌리고 싶다면 **설정 → 일반**에서 끕니다.

### 동작 방식

Agentty는 새 브랜치 `agentty/<이름>`으로 `git worktree add`를 실행합니다. 기준은 프로젝트 폴더에 지금 체크아웃된 브랜치가 아니라 **기본 브랜치**입니다. 그래서 한 세션이 다른 세션의 병합되지 않은 작업 위에 쌓이는 일이 없습니다.

트리는 프로젝트 바깥의 `~/.agentty/worktrees/<프로젝트>-<경로 해시>/<이름>/`에 만들어집니다. 프로젝트 폴더 안에는 두지 않습니다. 코드 사본이 그 안에 있으면 모든 검색, 파일 워처, 빌드가 그 사본까지 훑게 됩니다.

Agentty가 삭제하는 것은 그 폴더 아래의 트리뿐입니다. 이용자가 직접 만든 워크트리는 파일 패널에 표시만 되고 건드리지 않습니다.

## 파일 패널

**⌥⌘B**는 프로젝트 트리를 터미널 옆에 붙입니다. 프로젝트의 **모든 워크트리**와, 각 트리에서 누가 작업하고 무엇이 바뀌었는지도 함께 보여줍니다.

트리를 클릭하면 그 안의 파일이 보이고, 이미 작업 중인 세션이 있으면 그 터미널로 이동합니다.

나머지는 우클릭 메뉴에 있습니다. 거기서 작업 중인 터미널로 이동하거나, 새 터미널을 열거나, 파일 관리자에서 폴더를 보거나, 경로를 복사하거나, 트리를 삭제합니다. 폴더를 직접 지워 버린 트리도 같은 메뉴에서 정리할 수 있습니다.

삭제는 먼저 묻습니다. 다이얼로그가 브랜치 이름과 함께 무엇이 사라지는지 알려 줍니다. 워크트리와 그 폴더, 그리고 **워크트리와 브랜치 삭제**를 골랐다면 로컬 브랜치까지입니다. 그 브랜치를 푸시한 적이 있으면 원격에서도 지울지 함께 묻습니다. 기본은 꺼져 있고 로컬 브랜치가 실제로 삭제된 경우에만 원격도 삭제합니다. 어느 쪽이든 안전 여부는 git이 판단합니다. 커밋하지 않은 변경이 있는 트리는 남고, 다른 곳에 없는 커밋을 가진 브랜치도 남습니다.

탭이 아직 작업 중인 트리는 삭제되지 않습니다. 메뉴에서 삭제 항목이 아예 빠지고, 다른 방법으로 지우려 해도 묻는 대신 그 사실을 알려 줍니다. 먼저 그 탭을 닫아 주세요.

### 패널의 워크트리 목록

**워크트리** 섹션은 페인이 있는 저장소의 워크트리를 보여줍니다. 홈 폴더처럼 프로젝트가 모인 폴더에서는 그 아래에서 워크트리가 있는 프로젝트를 모두 찾아 프로젝트별로 묶어 보여줍니다. 각 묶음은 접을 수 있습니다. 가장 최근에 작업한 프로젝트가 맨 위이고, 그 안에서는 프로젝트 폴더 다음에 워크트리가 최신순으로 나옵니다. 각 행에는 마지막으로 작업한 시점(마지막 커밋 또는 가장 최근의 미커밋 변경)이 표시됩니다. 폴더 검색은 패널이 열려 있을 때만 하고, 새로 고침 버튼을 누르면 다시 검색합니다. 섹션은 끌어서 크기를 조절할 수 있습니다.

워크트리가 있으면 **파일** 버튼이 보라색으로 바뀌고 개수가 표시됩니다.

워크트리를 더블클릭하거나 우클릭해서 **이 터미널에 열기**를 고르면 그 셸에서 그대로 이어서 작업합니다(먼저 묻습니다). **정리하고 프로젝트 폴더로 돌아가기**는 워크트리를 지우고 터미널을 프로젝트로 되돌립니다. 브랜치가 병합됐고 커밋하지 않은 것이 없으면 바로 처리하고, 그렇지 않으면 다이얼로그가 무엇을 잃게 되는지 정확히 알려 줍니다. 에이전트, 실행 중인 셸, 다른 페인이 그 트리에서 작업 중이면 거부됩니다.

셸이 있던 워크트리 폴더가 삭제되면, 사라진 폴더 대신 프로젝트 폴더로 이동합니다.

### 삭제해도 남는 것

워크트리와 함께 브랜치가 지워지는 것은 기본 브랜치가 그 커밋을 모두 갖고 있을 때뿐입니다. 기본 브랜치에 없는 커밋이 있는 브랜치는 푸시했더라도 남습니다. [모니터링](/docs/monitoring)의 **워크트리 관리** 페이지도 마찬가지입니다. 무시된 빌드 폴더(`build/`, `out/`, `dist/`, `.cache/`, `coverage/`)는 안에 든 것을 보고 판단해 파일이 있으면 먼저 묻습니다. `target/`, `node_modules/` 등은 예전처럼 그냥 지워집니다.

## 병렬 작업

에이전트에게 작업을 나누라고 하면 됩니다 — "A, B, C를 병렬로". 에이전트가 Agentty에 요청하고 한 번 확인하면 각 작업이 자기 분할 페인과 자기 워크트리에서 시작됩니다.

이런 요청은 매번 확인을 거칩니다. 에이전트가 스스로 페인을 열 수는 없습니다.

## 파일 편집기

파일 패널에서 파일을 클릭하면 터미널 옆에서 열립니다. 주요 언어의 구문 강조, 짝으로 입력되는 괄호와 따옴표(맞는 괄호는 상자로 표시), 줄 주석 처리 **⌘/**, 줄 이동 **⌥↑** / **⌥↓**, 실행 취소와 다시 실행, **⌘S** 저장, 그리고 설치된 포매터(Prettier, google-java-format, ktlint, rustfmt, gofmt, Black)로, 없으면 언어 서버로 정렬하는 **⇧⌥F**를 지원합니다.

이미지(PNG, JPEG, GIF, WebP)는 화면에 맞게 줄여 미리보기로 열립니다. 에이전트가 바꾼 파일은 자동으로 다시 읽힙니다. 파일 탭을 오른쪽 클릭하면 나오는 메뉴(다른 파일 닫기, 경로 복사, 파일 관리자에서 보기도 있음)의 **기본 편집기로 열기**는 파일을 VS Code, Cursor 또는 시스템 편집기로 넘깁니다. 파일은 읽고 쓸 뿐, 실행되지 않습니다. git 저장소에서는 마지막 커밋 이후 바뀐 줄이 거터에 표시됩니다. 추가는 초록, 수정은 파랑, 삭제된 자리는 빨간 표시입니다. 표시를 누르면 커밋된 줄을 보여 주고, **되돌리기**로 그대로 되돌립니다. 긴 클래스나 함수 안쪽을 볼 때는 그 첫 줄이 화면 위에 고정됩니다(스티키 스크롤). 터미널의 경로를 **⌘-클릭**하면 여기서 열리고, 출력에 줄과 열이 있으면(`src/app.ts:42:7`처럼 컴파일러나 에이전트가 쓴 경우) 바로 그 위치로 갑니다.

### 코드 따라가기

Kotlin, Java, JavaScript, TypeScript, Python, HTML, CSS(Tailwind 포함), Rust, Go에서:

| | |
|---|---|
| **⌘P** | 파일 이름으로 이동. `@`는 이 파일의 심볼, `#`는 프로젝트의 심볼, `:`는 줄, `%`는 프로젝트 파일 속 텍스트 |
| **⇧⌘F** | 프로젝트의 모든 파일에서 텍스트 찾기 (위 상자의 `%`). 선택한 텍스트나 커서의 이름으로 시작합니다. 대문자를 넣으면 대소문자를 구분하고, 저장하지 않은 파일은 화면에 보이는 대로 찾습니다 |
| **F12** 또는 **⌘-클릭** | 커서 아래 이름이 정의된 곳으로 이동(**⌘**를 누른 채 이름 위에 올리면 이동하지 않고 정의를 미리 봄). import 경로 위에서는 그 파일을 열고, 정의 자체 위에서는 사용처 목록 |
| **⇧F12** 또는 **⌥F7** | 프로젝트에서 그 이름을 쓰는 모든 곳 |
| **⌘F12** | 구현으로 이동: 인터페이스를 구현한 클래스, 메서드를 재정의한 곳(언어 서버 필요) |
| **F8** / **⇧F8** | 파일의 다음 / 이전 문제로 이동하고 메시지 표시 |
| **⌃Space** | 자동 완성(이름을 입력하거나 `.` 뒤에서도 저절로 열림. ↩ 또는 ⇥로 넣고 Esc로 닫기) |
| 자동 완성 뒤 **⇥** | 채울 다음 자리(인수, 속성 값)로, 마지막에는 끝으로 |
| Emmet 약어(`ul>li.item*3`) 입력 후 **↩** | HTML과 `.tsx`·`.jsx` 파일의 마크업에서 첫 번째 자동 완성으로 나오고, 태그로 펼쳐짐(JSX에서는 `className`). ⇥로 빈 자리를 차례로 이동 |
| **F2** | 커서 아래 이름을 쓰는 모든 곳에서 바꾸기(언어 서버가 없으면 이 파일 안에서만) |
| **⇧⌥O** | import 정리: 정렬하고 쓰지 않는 것은 제거(언어 서버 필요) |
| **⌘.** | 언어 서버가 여기서 제안하는 빠른 수정과 리팩터링(거터의 전구는 그 줄에 수정이 있다는 표시) |
| **⇧⌘O** / **⌥⌘O** / **⌃G** | 이 파일의 심볼 / 프로젝트의 심볼 / 줄 |
| **⌃-** / **⌃⇧-** | 이동했던 위치로 뒤로·앞으로 |

정의는 프로젝트 파일에서 이름으로 찾습니다(`.gitignore`를 따르고 의존성·빌드 폴더는 제외). 따로 설치할 것이 없습니다. 같은 이름이 여러 곳에 정의돼 있으면 가까운 것부터 모두 보여 줍니다.

그 언어의 언어 서버가 설치돼 있으면 에디터는 언어 서버에 물어봅니다. 그래서 바로 맞는 정의로 가고, 실제 사용처만 보여 주며, **⌘**를 누른 채 이름 위에 올리면 타입이나 시그니처도 보여 줍니다. 언어 서버는 그 언어의 파일을 열면 저절로 시작되고, 파일이 속한 프로젝트 폴더(`Cargo.toml`, `go.mod`, `package.json`, `pyproject.toml`, Gradle·Maven 빌드가 있는 곳)에서 실행됩니다. 그래서 큰 저장소 안 하위 폴더의 프로젝트도 제대로 읽습니다.

| 언어 | 언어 서버(`PATH`에 있어야 함) |
|---|---|
| Rust | `rust-analyzer`(`rustup component add rust-analyzer`) |
| Go | `gopls` |
| TypeScript, JavaScript | 프로젝트나 사용자의 TypeScript 7(`tsc`), 또는 `typescript-language-server` |
| Python | `pyright`(`pyright-langserver`), `basedpyright` 또는 `pylsp` |
| Java | `jdtls` |
| Kotlin | JetBrains의 `kotlin-lsp`(`brew install JetBrains/utils/kotlin-lsp`) |
| CSS, SCSS, Less, HTML, JSON | `vscode-css-language-server`, `vscode-html-language-server`, `vscode-json-language-server`(`npm install -g vscode-langservers-extracted`) |

큰 프로젝트를 아직 읽는 중이거나 언어 서버가 아무것도 찾지 못하면, 위처럼 이름으로 찾습니다. rust-analyzer는 빌드 스크립트와 프로시저 매크로를 끈 채 실행되므로, 프로젝트를 열어도 그 코드가 실행되지 않습니다. 언어 서버가 프로젝트 자체의 코드를 실행하는 방식으로 켜지는 일은 없습니다. 프로젝트의 TypeScript는 패키지 매니저로 직접 설치한 경우(git이 `node_modules`를 추적하지 않음)에만 쓰고, jdtls는 Gradle 가져오기를 끈 채 시작하고, Maven 프로젝트의 빌드는 그 프로젝트에서 상태 표시줄의 **빌드 읽기**를 누른 뒤에만 읽습니다(빌드를 읽으면 `pom.xml`이 지정한 플러그인과 확장이 실행되므로, 그 전에는 파일 내용만 읽어 문법 오류만 보여 주며, 허용한 프로젝트는 **설정 → 프로젝트 → 언어 서버**에서 모두 해제할 수 있습니다). kotlin-lsp는 Gradle·Maven 빌드를 실행해서 프로젝트를 읽으므로, 그 프로젝트에서 **빌드 읽기**를 누른 뒤에만 켜집니다(빌드 파일이 없는 폴더는 읽지 않습니다).

언어 서버는 입력하는 동안 문제도 알려 줍니다. 오류는 빨간 물결 밑줄, 경고는 노란색, 참고는 파란색으로 표시되고, 줄번호와 스크롤바의 표시도 같은 색이 됩니다. 마우스를 올려 두면 메시지가 보입니다. 오류와 경고는 그 줄 끝에도 메시지가 표시됩니다(**설정 → 프로젝트 → 파일 편집기**에서 끌 수 있음). 파일 탭 이름은 그 파일의 가장 심각한 오류·경고 색으로 바뀝니다. 상태바에는 그 파일의 오류·경고 개수가 나오고, **F8**을 누르면 다음 문제로 이동합니다. rust-analyzer는 프로젝트를 빌드하지 않고(`cargo check`는 꺼 둠) 찾을 수 있는 문제만 알려 줍니다. 언어 서버가 수정 방법을 알고 있으면(예: **Add import from "./bad"**) 커서가 있는 줄의 거터에 전구가 나오고, 메시지 아래에도 수정 방법이 나옵니다. **⌘.**를 누르면 커서나 선택 영역에 쓸 수 있는 수정과 리팩터링을 모두 보여 줍니다. 언어 서버가 모르는 이름이라고 알린 경우(`undefined: Totl`, `Cannot find name 'onlyInStok'`)에는 파일과 프로젝트에서 철자가 가장 가까운 이름으로 **'Total'(으)로 바꾸기**도 나오며, AI 없이 바로 고칩니다. 수정은 열린 파일을 한 번에 바꾸므로 **⌘Z** 한 번으로 되돌릴 수 있고, 열려 있지 않은 파일은 바로 저장됩니다. 문제 메시지 아래와 **⌘.** 목록 맨 끝의 **AI로 고치기**를 누르면, 문제가 있는 위치와 언어 서버의 메시지가 연결된 세션에 전달됩니다. 상태바 오류 개수 옆의 반짝이 아이콘을 누르면 열린 파일의 오류를 한꺼번에 전달합니다. 입력하는 동안 언어 서버의 자동 완성 목록이 커서 아래에 나오고, 다른 파일의 이름을 고르면 import도 함께 추가됩니다. 언어 서버가 없으면 파일 안의 단어를 제안합니다. 함수 호출을 입력하는 동안에는 줄 위에 시그니처가 나오고, 지금 입력 중인 매개변수가 강조됩니다. 이름 위에 마우스를 잠시 올려 두면 타입이나 시그니처가 나오고, 상태바의 오류 개수를 누르면 열린 파일 전체의 문제가 코드와 함께 목록으로 나옵니다.

에디터 아래 상태바에는 지금 파일의 언어 서버가 표시됩니다. 설치되지 않았으면 **… 설치**가 나오고, 누르면 그 언어 서버의 공식 설치 명령(`rustup`, `go install`, `npm`, Homebrew)을 새 터미널 탭에서 실행합니다. 설치 명령에 필요한 도구가 없으면 공식 페이지를 엽니다. **설정 → 프로젝트 → 언어 서버**에서 전체 목록을 보고 서버마다 켜고 끌 수 있습니다(끄면 바로 멈춤). Agentty가 실행 중일 때 설치해도 저절로 연결됩니다. 언어 서버는 이 컴퓨터에서 실행되며, 코드는 어디에도 전송되지 않습니다.

### 코드 옆에서 에이전트와 함께 작업

편집기 막대의 **세션 연결**을 누르면 에이전트 터미널이 코드 오른쪽에 붙습니다(가장자리를 끌어 크기 조절). 기본은 활성 탭의 에이전트이고, 열에서 다른 세션을 고를 수 있습니다. 세션이 권한 승인이나 답변을 기다리면 막대의 칩에 표시되고, 누르면 세션이 보입니다.

- **코드를 선택**하면 **AI에게 지시**, **복사**, **정의로 이동**, **사용처** 막대가 뜹니다. **AI에게 지시**(또는 **⌘K**)에 쓴 지시는 파일과 선택한 줄 범위와 함께 연결된 세션으로 전달됩니다.
- **에이전트가 일하는 모습이 보입니다.** 에이전트가 파일을 바꾸면 바뀐 줄이 빛났다가 사라지고, 커서 자리에 에이전트 이름(`Claude-3f9a`)이 표시됩니다. Claude Code는 쓰기 직전의 위치도 보여 줍니다. 여러 세션이 동시에 작업할 수 있고, 세션마다 커서와 막대의 칩이 따로 생깁니다. 칩을 누르면 그 파일의 그 위치로 이동합니다.
- **따라가기**(막대의 눈 아이콘)를 켜면 에이전트가 바꾸려는 파일이 그 위치로 앞에 나옵니다(열려 있지 않으면 엽니다). 키보드 포커스는 가져가지 않고, 입력 중에는 기다리며, 터미널을 보고 있을 때는 아무것도 하지 않습니다. 보이는 범위 위·아래에서 작업 중인 에이전트는 그 가장자리에 표시되고, 누르면 그곳으로 스크롤합니다.
- **AI에게 지시**한 줄은 에이전트가 바꿀 때까지 표시됩니다. **⌥↩**는 질문만 보냅니다(파일을 바꾸지 말라고 전달).
- **에이전트 변경 검토.** 열린 파일에서 에이전트가 바꾼 곳마다 거터에 에이전트 색 막대가, 파일 탭에 점이 남습니다. 아래쪽 막대에서 변경을 차례로 보며 **되돌리기**(에이전트가 손대기 전으로 되돌리고 저장, ⌘Z로 다시 되돌릴 수 있음), **유지**(표시 지움), **모두 유지**를 고릅니다. **비교**는 바뀌기 전 줄과 지금 줄을 함께 보여 주고, 막대의 **변경 N**은 열린 모든 파일의 변경을 코드와 함께 목록으로 보여 주며, **⌥F5** / **⇧⌥F5**로 다음·이전 변경으로 이동합니다. 같은 줄을 에이전트가 다시 고치면 하나의 변경으로 합쳐집니다.
- **내 편집은 안전합니다.** 저장하지 않은 편집이 있는 파일을 에이전트가 쓰면, 서로 다른 줄이면 자동으로 합쳐지고 같은 줄일 때만 어떻게 할지 묻습니다. 에이전트가 위쪽에 줄을 넣어도 커서와 화면은 보던 코드에 그대로 있습니다.
- 코드 위 막대에 커서 위치(`ApiClient › save`)가 표시되고, 누르면 그곳으로 이동합니다. 정의·사용처 목록에서는 고른 위치 주변 코드가 옆에 보입니다.
