## git 페이지

**⇧⌘G**가 GitHub Desktop 형태의 페이지를 엽니다.

- 저장소와 브랜치 전환
- **fetch**(⇧⌘T), **pull**, **push**(⌘P), **새로 고침**(⌘R)
- 변경 사항을 파일별로 검토하고 원하는 것만 스테이지해 커밋(⌘↩)
- 히스토리 탐색과 브랜치 병합

Agentty는 이용자의 `git`을 그 설정과 자격 증명 그대로 사용합니다. 모든 명령은 비대화형으로 실행되므로, 보이지 않는 프롬프트에서 멈추는 일이 없습니다. 자격 증명 도우미가 처리하지 못하는 push라면 멈춰 있는 대신 메시지와 함께 실패합니다.

## 페인에서 바로

어느 페인이든 헤더의 브랜치 이름을 클릭하면 터미널을 떠나지 않고 브랜치 전환, pull, push, 이름 복사를 할 수 있습니다.

목록의 브랜치를 우클릭하면 **이 브랜치로 전환**, **이름 바꾸기…**, **여기서 새 브랜치…**, **이름 복사**, **브랜치 삭제**를 쓸 수 있습니다. 어디에도 병합되지 않은 커밋이 있는 브랜치는 한 번 더 물은 뒤에만 삭제합니다. 다이얼로그에서 원격 사본도 함께 지울 수 있습니다(**원격 브랜치(…)도 함께 삭제**). **서버(원격)에서 삭제**는 확인을 거쳐 모든 사람에게서 원격 브랜치를 지웁니다. git은 한 브랜치를 한 번에 한 폴더에서만 열 수 있어서, 다른 폴더가 그 브랜치를 쓰고 있어 전환이 거부되면 조용히 실패하는 대신 **그 폴더 열기**를 제안합니다.

### AI로 해결하기

병합이 충돌로 멈췄거나, 브랜치와 원격 브랜치가 갈라져 pull할 수 없거나, 해결되지 않은 충돌이 남아 있으면 메시지에 **AI로 해결하기**가 나타납니다. 저장소에서 Claude Code를 열고 없으면 Codex나 설치된 다른 에이전트를 열어 충돌 해결 지침을 전달합니다. 설치된 에이전트가 없으면 저장소에서 터미널만 엽니다. 병합이 진행 중일 때는 다른 병합을 시작하지 않습니다.

## 세션마다 하나의 워크트리

이미 다른 세션이 작업 중인 프로젝트에서 두 번째 AI 세션을 열면, Agentty가 어디서 시작할지 묻습니다. **새 워크트리 만들기**는 프로젝트 기본 브랜치에서 딴 새 브랜치의 전용 git 워크트리에서 시작해 두 에이전트가 같은 파일을 고치지 않게 합니다. **기존 워크트리 열기**는 같은 워크트리에서 새 세션만 시작합니다. 한 브랜치를 두 세션이 함께 보거나 작업할 때 쓰세요. 터미널에 `claude`나 `codex`를 직접 입력해도 같은 질문이 나옵니다.

- 워크트리는 `~/.agentty/worktrees/` 아래에, `agentty/<이름>` 브랜치로 만들어집니다.
- 모든 세션을 한 폴더에서 돌리고 싶다면 **설정 → 일반**에서 끕니다.

### 동작 방식

Agentty는 새 브랜치 `agentty/<이름>`으로 `git worktree add`를 실행하며 기준은 프로젝트 폴더가 현재 체크아웃한 브랜치가 아니라 **기본 브랜치**입니다. 그래서 한 세션이 다른 세션의 병합되지 않은 작업 위에 쌓이는 일이 없습니다.

트리는 프로젝트 바깥의 `~/.agentty/worktrees/<프로젝트>-<경로 해시>/<이름>/`에 만들어집니다. 프로젝트 폴더 안에는 두지 않습니다. 코드 사본이 그 안에 있으면 모든 검색, 파일 워처, 빌드가 그 사본까지 훑게 됩니다.

Agentty가 삭제하는 것은 그 폴더 아래의 트리뿐입니다. 이용자가 직접 만든 워크트리는 파일 패널에 표시만 되고 건드리지 않습니다.

## 파일 패널

**⌥⌘B**는 프로젝트 트리를 터미널 옆에 붙입니다. 프로젝트의 **모든 워크트리**와, 각 트리에서 누가 작업하고 무엇이 바뀌었는지도 함께 보여줍니다.

트리를 클릭하면 그 안의 파일이 보이고, 이미 작업 중인 세션이 있으면 그 터미널로 이동합니다.

나머지는 우클릭 메뉴에 있습니다. 거기서 작업 중인 터미널로 이동하거나, 새 터미널을 열거나, 파일 관리자에서 폴더를 보거나, 경로를 복사하거나, 트리를 삭제합니다. 폴더를 직접 지워 버린 트리도 같은 메뉴에서 정리할 수 있습니다.

삭제는 먼저 묻습니다. 다이얼로그가 브랜치 이름과 함께 무엇이 사라지는지 알려 줍니다. 워크트리와 그 폴더, 그리고 **워크트리와 브랜치 삭제**를 골랐다면 로컬 브랜치까지입니다. 그 브랜치를 푸시한 적이 있으면 원격에서도 지울지 함께 묻습니다. 기본은 꺼져 있고 로컬 브랜치가 실제로 삭제된 경우에만 원격도 삭제합니다. 어느 쪽이든 안전 여부는 git이 판단합니다. 커밋하지 않은 변경이 있는 트리는 남고, 다른 곳에 없는 커밋을 가진 브랜치도 남습니다.

탭이 아직 작업 중인 트리는 삭제되지 않습니다. 메뉴에서 삭제 항목이 아예 빠지고, 다른 방법으로 지우려 해도 묻는 대신 그 사실을 알려 줍니다. 먼저 그 탭을 닫아 주세요.

### 패널의 워크트리 목록

**워크트리** 섹션은 페인이 있는 저장소의 워크트리를 보여줍니다. 홈 폴더처럼 프로젝트가 모인 폴더에서는 그 아래에서 워크트리가 있는 모든 프로젝트를 프로젝트별로 묶어 보여주며 각 묶음은 접을 수 있습니다. 가장 최근에 작업한 프로젝트가 맨 위이고, 그 안에서는 프로젝트 폴더 다음에 워크트리가 최신순으로 나옵니다. 각 행에는 마지막으로 작업한 시점(마지막 커밋 또는 가장 최근의 미커밋 변경)이 표시됩니다. 폴더는 패널이 열려 있는 동안에만 검색하고, 섹션은 끌어서 크기를 조절할 수 있습니다. 새로 고침 버튼은 다시 검색합니다.

워크트리가 있으면 **파일** 버튼이 보라색으로 바뀌고 개수가 표시됩니다.

워크트리를 더블클릭하거나 우클릭해서 **이 터미널에 열기**를 고르면 그 셸에서 그대로 이어서 작업합니다(먼저 묻습니다). **정리하고 프로젝트 폴더로 돌아가기**는 워크트리를 지우고 터미널을 프로젝트로 되돌립니다. 브랜치가 병합됐고 커밋하지 않은 것이 없으면 바로 처리하고, 그렇지 않으면 다이얼로그가 무엇을 잃게 되는지 정확히 알려 줍니다. 에이전트, 실행 중인 셸, 다른 페인이 그 트리에서 작업 중이면 거부됩니다.

셸이 있던 워크트리 폴더가 삭제되면, 사라진 폴더 대신 프로젝트 폴더로 이동합니다.

### 삭제해도 남는 것

워크트리와 함께 브랜치가 지워지는 것은 기본 브랜치가 그 커밋을 모두 갖고 있을 때뿐입니다. 기본 브랜치에 없는 커밋이 있는 브랜치는 푸시했더라도 남으며 [모니터링](/docs/monitoring)의 **워크트리 관리** 페이지도 같습니다. 무시된 빌드 폴더(`build/`, `out/`, `dist/`, `.cache/`, `coverage/`)는 안에 든 파일을 기준으로 판단합니다. 파일이 들어 있으면 먼저 묻고, `target/`, `node_modules/` 등은 예전처럼 그냥 지워집니다.

## 병렬 작업

에이전트에게 작업을 나누라고 하면 됩니다 — "A, B, C를 병렬로". 에이전트가 Agentty에 요청하고 한 번 확인하면 각 작업이 자기 분할 페인과 자기 워크트리에서 시작됩니다.

이런 요청은 매번 확인을 거칩니다. 에이전트가 스스로 페인을 열 수는 없습니다.

## 파일 편집기

파일 패널에서 파일을 클릭하면 터미널 옆에서 열립니다. 주요 언어의 구문 강조, 실행 취소와 다시 실행, **⌘S** 저장, 그리고 설치된 포매터(Prettier, google-java-format, ktlint, rustfmt, gofmt, Black)로 정렬하는 **⇧⌥F**를 지원합니다.

에이전트가 바꾼 파일은 자동으로 다시 읽힙니다. **편집기에서 열기**는 파일을 VS Code, Cursor 또는 시스템 편집기로 넘깁니다. 파일은 읽고 쓸 뿐, 실행되지 않습니다.
