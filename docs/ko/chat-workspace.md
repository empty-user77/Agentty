채팅 작업공간은 위에 대화를, 아래에 에이전트 팀을 둡니다. 사용자는 채팅에서 **리드 에이전트**(Claude Code) 하나와 이야기합니다. 리드는 작업을 계획해 **워커**에게 나눠 맡기고, 그 결과를 **리뷰어**에게 검토받을 수 있습니다. 모두 채팅 아래 그리드에서 각자 터미널로 실행되므로 팀 전체가 일하는 모습을 한눈에 볼 수 있습니다.

## 여는 방법

- 시작 화면(또는 **새 작업공간**)에서 **채팅 · 팀**을 고른 뒤 프로젝트 폴더를 선택합니다.
- 또는 탭 옆 **+** 메뉴에서 **새 채팅 작업공간**을 고릅니다.

## 채팅의 브랜치

git 저장소에서는 채팅마다 자기 브랜치(`agentty/chat-…`, 채팅 막대에 표시)가 생기고, 리드는 그 브랜치의 워크트리에서 일합니다. 프로젝트 폴더는 건드리지 않습니다.

- 워커는 각자 새 브랜치의 워크트리를 받는데, 그 브랜치는 **채팅 브랜치의 최신 커밋**에서 시작합니다. 리드가 이미 머지한 작업을 다음 워커가 이어받을 수 있습니다.
- 리드는 워커의 작업을 확인한 뒤 그 브랜치를 채팅 브랜치에 머지합니다.
- 결과는 요청할 때만 프로젝트 폴더에 반영됩니다. 원격 저장소가 있으면 리드가 PR을 열고, 없으면 프로젝트 폴더에 커밋되지 않은 변경이 없을 때 그 폴더에 머지합니다.

커밋이 하나도 없는 저장소는 갈라질 지점이 없습니다. 이때 리드는 프로젝트 폴더에서 일하고, 워커는 리드가 첫 커밋을 만든 뒤 기본 브랜치에서 시작합니다.

## 동작 방식

1. 채팅에 씁니다. **Enter**는 전송, **Shift+Enter**는 줄바꿈입니다.
2. 리드는 작은 일은 직접 처리합니다. 큰 일은 계획을 세우고 `agentty tasks`로 워커를 시작합니다. 채팅 작업공간에서는 평소의 확인 창 없이 바로 시작됩니다. 채팅을 연 것 자체가 동의입니다.
3. 워커는 채팅 아래 그리드에 한 줄에 둘씩, 리뷰어를 포함해 한 번에 최대 **4개**까지 나타납니다. 네 자리가 모두 차 있으면 가장 먼저 끝난 것이 닫히고 그 자리에 새것이 들어갑니다. 닫힌 쪽의 브랜치와 세션은 남아 있어 세션 목록에서 이어갈 수 있습니다.
4. 워커가 한 턴을 마치면 Agentty가 리드에게 짧은 보고를 보냅니다. 보고에는 워커 이름, 브랜치, 폴더, 마지막 답변이 들어 있습니다. 리드는 결과를 검토해 머지하거나, 채팅으로 알려주거나, 워커에게 후속 지시를 보냅니다.

채팅 위 막대에는 리드 상태, 채팅 브랜치, 워커마다 칩이 표시됩니다. 칩을 누르면 해당 워커 터미널로 이동합니다. 워커가 승인이나 답변을 기다리면 채팅에도 알림이 뜹니다.

## 워커와 리뷰어

채팅 막대의 버튼 두 개로 누가 일할지 고릅니다.

| 버튼 | 선택지 | 정하는 것 |
|---|---|---|
| **워커** | Claude · Codex | 리드가 작업에 에이전트를 따로 지정하지 않았을 때 새 워커가 쓰는 에이전트 |
| **리뷰어** | 끔 · Claude · Codex | 머지 전에 워커 작업을 리뷰받으라고 리드에게 요청할지, 어떤 에이전트로 할지 |

**리뷰어**는 워커의 폴더에서 시작해 채팅 브랜치 대비 변경을 읽습니다. 테스트는 돌릴 수 있고, 아무것도 바꾸지 말라는 지시를 받습니다. Codex는 읽기 전용 샌드박스에서 돌고, Claude Code는 편집 도구 없이 돕니다(셸로는 여전히 쓸 수 있어서 이 경우는 지시에 의존합니다). 마지막 줄은 `Verdict: approve` 또는 `Verdict: changes needed`로 끝나고, 리뷰 보고는 워커 보고처럼 리드에게 갑니다. 리뷰어를 꺼 둔 상태에서도 리드가 직접 리뷰어를 띄울 수 있으며, 그때도 버튼에서 고른 에이전트가 쓰입니다.

선택은 채팅과 함께 저장됩니다.

## 리드의 터미널

채팅은 실제 Claude Code 세션을 보여주는 화면입니다. 채팅 막대의 **터미널**을 누르면 리드의 터미널이, **채팅**을 누르면 다시 채팅이 보입니다. 다음처럼 터미널에서만 답할 수 있는 경우에는 터미널이 저절로 나타납니다.

- 처음 실행할 때 폴더 신뢰 여부를 묻거나 로그인이 필요할 때
- 리드가 도구 승인이나 질문을 기다릴 때

거기서 답하면 채팅으로 돌아옵니다. 그 사이에 도착한 메시지는 리드가 응답할 수 있을 때까지 기다렸다가 전달됩니다. Agentty는 에이전트 화면에 승인이나 질문이 떠 있는 동안에는 아무것도 입력하지 않습니다.

## 리드가 쓰는 명령

| 명령 | 하는 일 |
|---|---|
| `agentty tasks --plan <plan.json>` / `--title … --prompt-file …` | 워커 시작(여기서는 확인 창 없이) |
| `agentty tasks status` | 워커 목록, 각자 하는 일, 채팅의 선택 |
| `agentty tasks send --to <이름> --prompt <내용>` | 워커에게 후속 메시지 보내기 |
| `agentty tasks result --to <이름>` | 워커의 마지막 답변 다시 보기 |
| `agentty tasks stop --to <이름>` | 워커 닫기(브랜치와 세션은 남음) |
| `agentty tasks review --worker <이름> [--prompt <관점>] [--agent claude\|codex]` | 워커 작업의 리뷰어 시작 |

이 명령들은 채팅 작업공간의 리드만, 자기 워커에게만 쓸 수 있습니다.

## 알아두면 좋은 점

- 워커는 자기 브랜치에 커밋합니다. 푸시나 PR 생성은 리드에게 요청했을 때만 합니다.
- 워커와 리뷰어 하나하나가 완전한 에이전트 세션이라, 넷이 동시에 일하면 요금제 한도가 하나일 때보다 빨리 줄어듭니다.
- 채팅과 그리드 사이의 경계선을 끌어 어느 쪽이든 넓힐 수 있습니다. 레이아웃은 작업공간과 함께 저장됩니다.
- 설정에서 **에이전트가 병렬 작업을 시작할 수 있음**을 끄면 채팅의 리드도 워커를 시작할 수 없습니다.
- 채팅 브랜치 기능 이전에 연 채팅은 계속 프로젝트 폴더에서 일합니다.
