채팅 작업공간은 위에 대화를, 아래에 에이전트 팀을 둡니다. 사용자는 채팅에서 **리드 에이전트**(Claude Code) 하나와 이야기합니다. 리드는 작업을 계획하고 조각으로 나눠 **워커**에게 맡깁니다. 워커는 채팅 아래 그리드에서 각자 터미널로 실행되므로 팀 전체가 일하는 모습을 한눈에 볼 수 있습니다.

## 여는 방법

- 시작 화면(또는 **새 작업공간**)에서 **채팅 · 팀**을 고른 뒤 프로젝트 폴더를 선택합니다.
- 또는 탭 옆 **+** 메뉴에서 **새 채팅 작업공간**을 고릅니다.

리드는 프로젝트 폴더에서 바로 일합니다. 워커는 각자 프로젝트 기본 브랜치에서 새 브랜치를 만든 별도 git 워크트리에서 일하므로 서로 같은 파일을 건드리지 않습니다.

## 동작 방식

1. 채팅에 씁니다. **Enter**는 전송, **Shift+Enter**는 줄바꿈입니다.
2. 리드는 작은 일은 직접 처리합니다. 큰 일은 계획을 세우고 `agentty tasks`로 워커를 시작합니다. 채팅 작업공간에서는 평소의 확인 창 없이 바로 시작됩니다. 채팅을 연 것 자체가 동의입니다.
3. 워커는 채팅 아래 그리드에 한 줄에 둘씩, 한 번에 최대 **4개**까지 나타납니다. 네 자리가 모두 차 있으면 가장 먼저 끝난 워커가 닫히고 그 자리에 새 워커가 들어갑니다. 닫힌 워커의 브랜치와 세션은 남아 있어 세션 목록에서 이어갈 수 있습니다.
4. 워커가 한 턴을 마치면 Agentty가 리드에게 짧은 보고를 보냅니다. 보고에는 워커 이름, 브랜치, 폴더, 마지막 답변이 들어 있습니다. 리드는 결과를 검토해 채팅으로 알려주거나 워커에게 후속 지시를 보냅니다.

채팅 위 막대에는 리드 상태와 워커마다 칩이 표시됩니다. 칩을 누르면 해당 워커 터미널로 이동합니다. 워커가 승인이나 답변을 기다리면 채팅에도 알림이 뜹니다.

## 리드의 터미널

채팅은 실제 Claude Code 세션을 보여주는 화면입니다. 채팅 막대의 **터미널**을 누르면 리드의 터미널이, **채팅**을 누르면 다시 채팅이 보입니다. 다음처럼 터미널에서만 답할 수 있는 경우에는 터미널이 저절로 나타납니다.

- 처음 실행할 때 폴더 신뢰 여부를 묻거나 로그인이 필요할 때
- 리드가 도구 승인이나 질문을 기다릴 때

거기서 답하면 채팅으로 돌아옵니다. 그 사이에 도착한 워커 보고는 리드가 응답할 수 있을 때까지 기다렸다가 전달됩니다.

## 리드가 쓰는 명령

| 명령 | 하는 일 |
|---|---|
| `agentty tasks --plan <plan.json>` / `--title … --prompt-file …` | 워커 시작(여기서는 확인 창 없이) |
| `agentty tasks status` | 워커 목록과 각자 하는 일 |
| `agentty tasks send --to <이름> --prompt <내용>` | 워커에게 후속 메시지 보내기 |

`status`와 `send`는 채팅 작업공간의 리드만, 자기 워커에게만 쓸 수 있습니다.

## 알아두면 좋은 점

- 워커는 자기 브랜치에 커밋합니다. 푸시나 PR 생성은 리드에게 요청했을 때만 합니다. 리드는 요청을 받았거나 머지가 포함된 계획을 승인받았을 때만 브랜치를 머지합니다.
- 워커 하나하나가 완전한 에이전트 세션이라, 넷이 동시에 일하면 요금제 한도가 하나일 때보다 빨리 줄어듭니다.
- 채팅과 그리드 사이의 경계선을 끌어 어느 쪽이든 넓힐 수 있습니다. 레이아웃은 작업공간과 함께 저장됩니다.
- 설정에서 **에이전트가 병렬 작업을 시작할 수 있음**을 끄면 채팅의 리드도 워커를 시작할 수 없습니다.
