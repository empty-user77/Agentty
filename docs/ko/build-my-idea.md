description: 몇 문장과 첨부 파일로 프로젝트 폴더를 만들어, 에이전트가 바로 작업을 시작하게 하기.
---

"아이디어로 시작하기"는 아직 프로젝트가 없을 때 쓰는 기능입니다. 원하는 것을 짧은 대화로 설명하고 가진 자료를 첨부하면 에이전트가 바로 출발할 수 있는 폴더를 Agentty가 만들어 줍니다.

시작 페이지, **+** 메뉴, 명령 팔레트에서 열 수 있습니다. 제안 자체가 필요 없으면 **설정 → 일반**에서 끕니다.

## 무엇이 만들어지는가

새 폴더(기본 위치는 `~/AgenttyProjects`)에 다음이 들어갑니다.

| 경로 | 내용 |
|---|---|
| `docs/idea/IDEA.md` | 작성한 내용을 순서대로 |
| `docs/idea/attachments/` | 첨부한 파일의 사본 |
| `docs/idea/BUILD_GUIDE.md` | 작업 방식: 먼저 계획하고, 만들고, 실시간으로 확인하기 |
| `.claude/settings.json` | 에이전트가 명령마다 묻지 않고 패키지를 설치하고 개발 서버를 실행할 수 있는 권한 |

그 밖의 것은 비워 둡니다. 그래야 `create-next-app`, `create vite` 같은 프로젝트 생성기가 그 폴더를 그대로 받아들입니다.

첨부는 20개, 개당 20MB까지입니다.

## 그다음

Agentty가 그 폴더에서 에이전트를 열고 첫 프롬프트까지 준비해 둡니다. 결과가 만들어지는 모습은 [인앱 브라우저](/docs/in-app-browser)에서 바로 봅니다. **개발 방식**으로 누가 만들지 고릅니다.

- **에이전트 팀** (Claude Code나 Codex가 만들고 설정에서 오케스트레이션이 켜져 있을 때 기본값): 에이전트가 [오케스트레이션](/docs/session-flow)을 이끕니다. 팀은 아이디어에서 코드까지 한 단계씩 나아가고, 단계마다 다음 단계가 쓸 문서를 `docs/design/`에 남깁니다.
  1. 아이디어 분석: 문제, 사용자, 대안, 위험, 그리고 스스로 정한 가정
  2. 아이디어 도출: 가치, 기능 우선순위, 데모 범위
  3. 기획(PRD): 인수 조건이 있는 사용자 스토리, 화면과 흐름
  4. HLD(상위 설계): 스택, 아키텍처, 데이터 모델, 페이지
  5. LLD(상세 설계): 파일, 컴포넌트와 인터페이스, 개발 단위로 나눈 작업
  6. 에이전트 구성: 프로젝트 하네스와 개발 단위마다 개발자 한 명
  7. 개발: 기반을 먼저, 개발 단위는 나란히, 마지막에 브라우저 품질 점검과 PRD 기준 검토

  한 단계 안에서는 여러 에이전트가 나란히 일하고(예: 분석 단계의 사용자·시장·실현 가능성), 단계끼리는 순서대로 이어집니다. 오케스트레이션 화면에 웨이브로 표시됩니다.
- **에이전트 하나**: 에이전트가 혼자 계획하고 만듭니다.

공개할 준비가 되면 [Launch](/docs/launch)가 배포합니다.
