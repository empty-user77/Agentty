**⇧⌘F**가 오케스트레이션을 엽니다. (파일 편집기에서는 ⇧⌘F가 프로젝트 파일 검색입니다. 오케스트레이션은 **보기** 메뉴에서도 열 수 있습니다.) 탭이 두 개 있습니다. **워크플로**는 세션의 일이 어떻게 나뉘어 어디까지 진행됐는지 보여 주고, **세션 연결**은 세션끼리 연결해 컨텍스트를 공유합니다.

## 오케스트레이션 시작하기

목표를 적으면 오케스트레이터 에이전트가 나머지를 합니다. 목표에 맞는 에이전트 팀을 짜서 계획을 보여 주고, 웨이브로 실행한 뒤 결과를 검수까지 받습니다.

홈 화면의 **오케스트레이션**, 탭 오른쪽 클릭 메뉴의 **새 오케스트레이션 탭**, 새 작업공간의 시작 화면, 또는 이 화면 오른쪽 위의 **새 오케스트레이션**에서 시작합니다. 시작 창에는:

- **목표** — 팀이 해낼 일. 아래 예시를 누르면 채워집니다: 시장 조사, 웹앱을 직접 써 보며 만드는 튜토리얼, 기능 구현과 리뷰, 실패하는 테스트 고치기.
- **모델** — 균형(작업은 Sonnet, 검수는 Opus), 최고 품질(전부 Opus), 절약(작업은 Haiku, 검수는 Sonnet). 계획에는 에이전트마다 쓸 모델이 적힙니다. Claude Code가 리드일 때만 보이며, Codex가 리드면 각 CLI가 자기 기본 모델을 씁니다.
- **폴더** — 팀이 일할 곳.
- **함께 쓸 AI** — 리드는 항상, 그리고 이 Mac에 설치된 다른 에이전트(Claude Code, Codex, Gemini CLI, Antigravity CLI)를 각각 켜고 끕니다. Claude Code가 설치되어 있으면 Claude Code가, 없으면 Codex가 리드를 맡습니다. 둘 다 없으면 오케스트레이션을 시작할 수 없습니다. 계획은 일마다 강점이 맞는 에이전트에게 맡기고(정밀한 코드 수정과 리뷰는 Codex, 아주 큰 입력은 Gemini), 그 에이전트들의 권한 확인은 끄지 않습니다.

Codex 리드에는 서브에이전트가 없습니다. 그래서 웨이브의 에이전트를 각각 에이전트 CLI 프로세스로 실행하고, 시작과 끝을 Agentty에 알립니다(`agentty plan --start` / `--done`). 이 화면은 Claude Code 리드일 때와 똑같이 진행을 따라갑니다. Codex는 이 명령들을 샌드박스 밖에서 실행하기 전에 승인을 묻습니다.

새 작업공간은 처음에 만들어지는 **오케스트레이션** 그룹에 들어가고, 원하는 그룹으로 옮길 수 있습니다. 시작하면 이 화면에 그 워크플로가 나옵니다. 계획이 준비되면 막대가 뜹니다. **계획 보기**는 오케스트레이터 패널을 열고, **수정 요청**은 메시지를 보내고, **시작**은 계획을 실행합니다. 따로 브랜치가 필요한 일은 병렬 세션(`agentty tasks`)으로 가고, 마지막에 검수 에이전트가 결과를 목표와 대조한 뒤 오케스트레이터가 보고로 마무리합니다.

## 따라가기, 이어하기, 중단

오케스트레이터 패널 맨 위에는 이 화면과 같은 말로 상태를 보여 주는 막대가 있습니다: 계획 세우는 중, 계획 준비됨(**시작**), 실행 중(작업 중인 에이전트 수와 완료 수), 완료, 중단됨, 중지됨. **워크플로 보기**를 누르면 이 화면으로 옵니다. 사이드바와 메뉴 막대에는 그 작업공간이 오케스트레이션 아이콘으로, 상태 색으로 표시됩니다.

오케스트레이션은 재시작해도 남습니다. 실행 중에 Agentty가 종료되거나 강제 종료되면 에이전트도 함께 멈춥니다. 그러면 막대와 이 화면에 **중단됨**이 뜨고, **이어하기**를 누르면 필요하면 세션을 다시 열어 이미 끝난 일은 두고 남은 일만 이어서 실행합니다. **전체 중단**(확인 후)은 오케스트레이터의 현재 작업과 아직 돌고 있는 모든 에이전트를 멈추고, 나중에 **이어하기**로 계속할 수 있습니다. **삭제**는 오케스트레이션을 목록에서 지우고(실행 중이면 먼저 멈춤), 원하면 터미널도 닫습니다. 만든 파일은 그대로 남습니다.

설정은 **설정 → AI 설정 → 오케스트레이션**에 있습니다: 사용 여부, 새 오케스트레이션의 기본 모델, 기본으로 함께 쓸 다른 AI, 계획을 보여 준 뒤 **시작**을 기다릴지, 새 작업공간과 새 탭 중 어디에 열지.

## 워크플로

왼쪽은 스레드 목록입니다. Agentty에서 실행 중인 에이전트 세션이 상태 색 점과 함께 나오고, 에이전트가 `agentty tasks`로 시작한 병렬 작업 묶음도 나옵니다. 하나를 고르면 그 워크플로가 보입니다.

- 맨 위: 마지막으로 시킨 일(`$ …`)과 세션 이름.
- 오케스트레이터 줄: 메인 에이전트의 상태, 웨이브 수, 끝난 서브 에이전트 수, 쓰고 있는 모델 수. **열기**는 그 패널로 가고, **메시지**는 그 패널에 입력한 것처럼 한 줄을 보내고, **중단**은 지금 턴을 멈춥니다(패널에서 Esc를 누른 것과 같음).
- 그래프: 오케스트레이터 다음에 서브 에이전트들이 웨이브별로 한 열씩 나옵니다. 오케스트레이션의 웨이브는 계획에서 옵니다. 계획이 나오는 순간 모든 에이전트가 그래프에 올라오고, 아직 시작하지 않은 에이전트는 대기로 보이며, 각자 기다리는 에이전트에서 선이 이어져 일이 웨이브에서 웨이브로 넘어가는 것이 보입니다. 다른 세션은 같은 시간에 돌았던 서브 에이전트가 한 웨이브입니다. 일하는 중인 웨이브에는 밑줄이 그어집니다. 카드마다 실행 중·완료·대기와 걸린 시간, 에이전트 종류와 모델, 지금 단계나 마지막 한마디가 나옵니다. 실행 중인 웨이브로 가는 선은 움직입니다. 카드를 누르면 그 서브 에이전트의 기록이 열립니다.
- 맨 아래: 서브 에이전트들의 최근 단계가 실시간으로 나옵니다.

병렬 작업 묶음은 작업들이 한 웨이브로 나오고, 각자 브랜치(또는 폴더)와 패널 상태를 보여 줍니다. 누르면 그 패널로 갑니다.

그래프의 빈 곳을 끌거나 휠을 굴리면 이동합니다. ⌘ 또는 Ctrl과 휠, 또는 오른쪽 아래 버튼으로 확대·축소하고, **전체 보기**로 한눈에 봅니다.

## 세션 연결

한 세션에서 다른 세션으로 선을 끌면 받는 쪽이 보낸 쪽의 컨텍스트를 받습니다. 무엇을 작업 중인지, 무엇을 결정했는지, 어디까지 왔는지입니다. Claude Code와 Codex 사이에서도 동작합니다.

Claude Code 세션 둘을 연결하면, 여기서 선을 그었든 터미널의 링크 버튼으로 창을 골랐든 직접 연결됩니다. 두 세션이 서로 메시지를 주고받습니다. 선을 시작한 세션은 상대 세션 프로젝트의 일을 직접 하지 말고 상대에게 넘기라는 안내를 받고, 상대 세션은 일을 마치면 결과를 알려 줍니다. 막 시작했거나 아직 이어서 여는 중인 세션은 몇 초 기다립니다. 그래도 서로 메시지를 보낼 수 없으면 대화 내용만 한쪽으로 넘기고 그렇다고 알려 줍니다.

세션이 많을 때는 화면을 옮겨 가며 봅니다. 스크롤하거나 빈 곳을 끌면 화면이 움직이고, **⌘** + 스크롤은 포인터를 중심으로 확대·축소합니다. 오른쪽 아래 버튼으로 축소·확대, 100%로 되돌리기, 모든 세션이 보이게 맞추기를 할 수 있습니다.

### 연결 방식

| 방식 | 동작 |
|---|---|
| 한 번 | 선을 그은 시점의 컨텍스트를 전달 |
| **라이브** | 보낸 쪽의 새 턴이 생길 때마다 받는 쪽으로 전달 |
| 양방향 | 서로에게 전달 — 컨텍스트 터널 |

라이브 연결을 쓰면 직접 복사하지 않아도 두 번째 에이전트가 계속 상황을 따라옵니다. 양방향 연결을 쓰면 두 에이전트가 같은 문제를 절반씩 맡으면서도 상대가 방금 한 일을 압니다.

### 무엇이 전달되는가

대화의 요약입니다. `~/.agentty/handoffs/`에 파일로 써서 받는 에이전트에게 넘깁니다. 프롬프트와 응답을 턴 단위로 재생하지는 않습니다.

### 언제 무엇을 쓰나

- **한 번** — 관련된 작업에 두 번째 에이전트를 시작하면서 맥락을 알고 출발하게 할 때.
- **라이브** — 한쪽이 구현하고 다른 쪽이 리뷰하거나 문서를 쓰거나 테스트를 지켜볼 때.
- **양방향** — 두 에이전트가 기능을 나눠 맡았고 서로 어긋나면 안 될 때.

연결을 끄면 전달이 멈춥니다. 이미 전달된 내용은 받는 쪽의 대화에 남습니다.
