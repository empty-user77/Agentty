---
title: 에이전트 상태
description: Agentty가 각 에이전트의 상태를 알아내고 알려 주는 방식.
---

Agentty는 실행한 에이전트를 지켜보면서 각 에이전트가 작업 중인지 끝났는지 나를 기다리는지 보여줍니다.

## 상태가 보이는 곳

- **사이드바** — 각 워크스페이스 행이 그 안의 에이전트 상태를 나타냅니다.
- **페인 테두리** — 에이전트가 질문하거나 권한을 요청하면 켜지고, 클릭할 때까지 유지됩니다.
- **에이전트 페인 위의 상태 바** — 모델, 컨텍스트 창, 사용 한도, 브랜치, 폴더.
- **알림** — 에이전트가 끝나거나 답을 기다릴 때. 클릭하면 해당 페인이 열립니다.
- **⇧⌘U** — 가장 최근의 미확인 페인으로 이동.
- **미니 모드와 메뉴 바** — 창을 앞에 두지 않고도 상태를 확인.

## 컨텍스트 창

상태 바의 컨텍스트 수치는 게이지입니다. 클릭하면 **컨텍스트 메모리** 패널이 열립니다. 컨텍스트를 시스템·도구, 메모리 파일, 스킬, 요약, 대화로 나눠 보여 주고, 마지막 압축 이후 읽거나 수정한 파일도 알려 줍니다.

창 크기는 에이전트가 직접 알려 준 값을 씁니다. Claude Code는 상태 줄로, Codex는 세션 기록으로 알려 주며, 모델 이름으로 짐작하지 않습니다. 아직 알려 주지 않았으면 게이지는 사용 중인 토큰 수만 보여 주고 퍼센트는 표시하지 않습니다.

패널에는 그 수치 옆에 **압축** 버튼이 있습니다. 수치와 상관없이 에이전트 자신의 압축 명령(Claude Code, Codex)을 실행합니다. 긴 작업을 시작한 뒤가 아니라 시작하기 전에 여유를 만들어 둘 수 있습니다. 상태 바 자체의 압축 버튼은 게이지가 주황색으로 바뀌는 70%부터 나타납니다.

## 상태의 종류

| 상태 | 의미 |
|---|---|
| 작업 중 | 도구를 실행하고 있음 |
| 생각 중 | 턴이 열린 상태, 도구 호출 사이 |
| 입력 대기 | 질문했거나 권한을 요청함 |
| 완료 | 턴이 끝남 |
| 유휴 | 실행 중인 것 없음 |

## 서브 에이전트

에이전트에게 서브 에이전트가 있으면 페인 헤더에 전체 중 몇 개가 실행 중인지(`1/3`) 보입니다. 이것을 클릭하면 **서브 에이전트** 창이 열립니다. 사이드바의 워크스페이스 카드에 나온 서브 에이전트를 ⌘-클릭해도 열리고, 오케스트레이션 **워크플로**에서 서브 에이전트 카드를 클릭하면 그 서브 에이전트를 고른 채로 열립니다. 창은 제목 표시줄로 옮기고 모서리로 크기를 바꿉니다. **별도 창으로 열기**를 누르면 Agentty 창 밖의 독립된 창이 됩니다.

창은 같은 서브 에이전트를 두 가지로 보여 줍니다.

- **오피스** — 실행 중인 서브 에이전트가 책상에 앉아 지금 하는 일을 말풍선으로 말하고, 세션 자신의 에이전트는 아래쪽 콘솔에서 일합니다. 끝난 서브 에이전트는 보고서 첫 줄을 들고 **휴게실**에 모입니다. **내보내기**는 하나를, **모두 내보내기**는 전부를 화면에서 치우며, 대화 기록은 그대로 남습니다. 한 층에 다 앉지 못하면 층이 늘어납니다.
- **타임라인** — 서브 에이전트마다 막대 하나를 같은 시간축에 그리고 실행 중인 도구 종류로 색을 칠합니다. 옆 목록에는 각자의 현재 단계가 나옵니다.

서브 에이전트를 클릭하면 로그를 읽을 수 있습니다. 도구 호출은 짧은 문장("app.ts 읽는 중")으로, 맡은 작업·중간 메모·보고서는 Markdown 서식대로 보입니다. **이 서브 에이전트 중지**는 실행 중인 서브 에이전트 하나를 다음 도구 호출에서 끝냅니다. 세션과 다른 서브 에이전트는 계속 일합니다.

### 예약된 작업

Claude Code 세션에 예약된 작업이 있는 동안 페인 헤더에 개수와 함께 시계가 보입니다. 세션의 cron 작업(`/loop 5m`이 만드는 것도 포함)과 스스로 간격을 정하는 `/loop`의 다음 턴을 셉니다. 클릭하면 목록이 열립니다. 작업마다 프롬프트, **반복**·**한 번**·**루프** 여부, 다음 실행 시각이 나옵니다(작업은 세션이 대기 중일 때만 실행되므로 시각이 지난 작업은 "대기 중이면 실행"으로 표시됩니다). 휴지통 아이콘을 누르면 하나를 지웁니다. Agentty가 세션에 삭제를 요청하고 세션이 다음 턴에 지우므로, 답을 기다리는 질문이 있으면 먼저 답하세요. Codex 페인에는 시계가 없습니다. Codex의 예약 작업은 Codex 데스크톱 앱에 속합니다.

## 동작 방식

Agentty는 페인을 시작할 때 명령줄로 상태 훅을 전달합니다. 에이전트는 이용자 계정만 접근할 수 있는 로컬 전용 소켓으로 상태를 보고합니다. 프로젝트나 에이전트의 설정 파일에는 아무것도 기록하지 않습니다.

## 알림

**설정 → 알림**에서 정합니다.

- 에이전트가 끝나거나 입력이 필요할 때의 시스템 알림.
- Agentty가 맨 앞에 있을 때도 알릴지 여부.
- 질문과 권한 요청은 해당 페인을 보고 있지 않는 한 항상 알립니다.
- 에이전트가 같은 질문을 여러 번 보고해도 질문 하나당 알림은 한 번입니다. 답한 뒤 새 질문이 오면 다시 알립니다.

### 알림에서 바로 허용·거부

Claude Code나 Codex의 권한 요청 알림에는 요청 내용(도구, 명령이면 그 내용)과 **허용** · **거부** 버튼이 붙습니다. macOS 알림과 미니 창 말풍선 모두 같습니다. 허용은 "Yes"로 한 번 허락하고, 거부는 "No"(Esc)로 답해 에이전트가 다른 지시를 기다리게 합니다. 어느 쪽이든 Agentty 창을 앞으로 띄우지 않습니다. "다시 묻지 않기"는 터미널에서만 고를 수 있습니다.

Agentty는 그 요청이 화면에서 아직 기다리는 동안에만 답을 입력합니다. 이미 터미널에서 답했거나 에이전트가 다음으로 넘어갔다면 버튼을 눌러도 입력하지 않고 해당 페인을 엽니다. macOS에서 허용은 Mac 잠금이 풀려 있어야 합니다. 알림 스타일이 배너면 버튼은 알림에 마우스를 올렸을 때 보입니다. 시스템 설정 → 알림에서 Agentty를 **알림** 스타일로 바꾸면 계속 표시됩니다. 여러 답 중 하나를 고르는 질문은 터미널에서 답합니다.
- "맨 앞"은 그 순간 Agentty가 활성 앱인지로 판단합니다.

### 휴대폰으로 받기

같은 화면에서 **Slack**, **Discord**, **Telegram**을 연결하면 자리를 비워도 질문을 받을 수 있습니다. 에이전트가 나를 찾을 때만 보낼지 작업을 끝냈을 때도 보낼지, 그리고 에이전트가 무엇을 물었는지 포함할지 선택할 수 있습니다.

Slack과 Discord는 두 가지 방식 중에서 고릅니다. 웹훅 주소를 쓰거나, 봇 토큰과 쓸 채널을 지정합니다 — Slack은 `#general`·`general`·채널 ID를 받고, Discord는 채널 ID를 받습니다. Telegram은 언제나 봇이며 쓸 대화를 지정합니다.

웹훅 주소와 봇 토큰은 설정 파일이 아니라 운영체제의 자격 증명 저장소에 보관됩니다.
