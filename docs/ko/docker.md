compose 파일이나 Dockerfile이 있거나 자체 컨테이너를 가진 프로젝트에서는, 상태 바에 그 프로젝트의 컨테이너가 몇 개 실행 중인지 표시됩니다(🐳 3 running). 클릭하면 패널이 열립니다.

Agentty는 프로젝트 루트에서 `compose.yaml`, `compose.yml`, `docker-compose.yml`, `docker-compose.yaml`을 찾습니다. `docker compose` 자신이 쓰는 이름과 순서 그대로입니다. compose 파일이 없으면 그 프로젝트의 컨테이너를 대신 나열합니다.

패널은 활성 페인의 워크트리를 따라가므로, 다른 프로젝트의 페인으로 옮기면 보이는 컨테이너도 바뀝니다.

## 패널이 보여주는 것

compose 서비스 또는 컨테이너마다 이미지, 상태(실행 중, 중지됨, 비정상), 포트를 보여줍니다.

## 할 수 있는 일

| 동작 | 비고 |
|---|---|
| 서비스 시작 / 중지 / 재시작 | |
| `compose up -d` | 이미지를 먼저 받을 수 있어 시간이 걸릴 수 있습니다 |
| `compose down` | **두 번 확인합니다.** 볼륨은 유지됩니다 |
| 로그 | 새 탭에서 열리므로 작업하면서 켜 둘 수 있습니다 |

## 일부러 읽지 않는 것

**환경 값은 읽지도, 보여주지도 않습니다.** compose 파일과 그 옆의 `.env`에는 데이터베이스 비밀번호가 흔히 들어 있고, `docker compose config`는 그것을 전부 펼쳐서 출력합니다. Agentty는 이름, 이미지, 상태, 포트만 읽습니다.

모든 Docker 명령은 셸을 거치지 않고 인자 배열로 실행되며, 서비스나 컨테이너 이름은 Docker가 먼저 보고한 뒤 유효성 검사를 통과해야만 명령에 전달됩니다. compose 파일에 잘못된 이름이 있어도 명령으로 바뀌지 않습니다.

## 패널이 비어 있다면

- Docker 데몬이 아직 시작 중일 수 있습니다. 목록 조회에는 15초 제한이 있어 느린 데몬이 패널을 멈추게 하지 않습니다.
- 프로젝트 루트에 위 네 가지 compose 파일 이름 중 하나가 있는지, 또는 해당 프로젝트로 라벨링된 컨테이너가 있는지 확인하세요.
