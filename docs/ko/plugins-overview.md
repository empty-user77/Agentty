description: 플러그인이 Agentty에 무엇을 더하는지, 마켓플레이스나 내 폴더에서 설치하는 법, 그리고 믿고 쓰기 전에 확인할 것.

플러그인은 Agentty를 다른 앱과 연결하고 터미널에 도구를 더합니다. 터미널 옆에 **패널**을 두고, 에이전트 페인 위에 **버튼**을 추가하고, **명령 팔레트**에 항목을 넣고, 텍스트를 **프롬프트**로 에이전트에 넘길 수 있습니다. 그 프롬프트가 어디로 갈지는 플러그인이 묻지 않는 한 플러그인이 정합니다. 그래서 카드의 권한을 읽어 볼 가치가 있습니다.

직접 만들고 싶다면 [플러그인 빠른 시작](/docs/plugin-quickstart)부터 보세요.

## 플러그인 페이지

액티비티 바의 퍼즐 아이콘, **보기 → 플러그인**, 또는 명령 팔레트(⇧⌘P → "플러그인")로 엽니다.

- **설치됨** — 보유한 모든 플러그인과, 무엇을 더하고 무엇을 할 수 있는지.
- **마켓플레이스** — Agentty가 제공하는 플러그인 목록. 자체 플러그인도 포함됩니다. 아래를 참고하세요.
- **사용 가능** — Agentty에 기본 포함된 플러그인. 연동 대상 앱이 설치돼 있으면 **추천**으로 표시됩니다.
- **직접 만들기** — AI로 플러그인을 만들거나, Git 저장소나 폴더에서 설치합니다.

설치된 플러그인마다 **활성화/비활성화**, **패널 열기**, **재시작**(코드 수정 후), **업데이트**(내장 플러그인의 새 버전이 나왔을 때), **로그**(플러그인이 출력한 내용과 크래시), **Finder에서 보기**, **삭제**(두 번 눌러 확인)가 있습니다.

플러그인은 Agentty 실행 시가 아니라 처음 사용할 때 시작되므로, 쓰지 않는 플러그인은 아무 비용도 들지 않습니다.

## 설치

| 출처 | 방법 |
|---|---|
| 마켓플레이스 | *마켓플레이스* 카드의 **설치** |
| 내장 | *사용 가능* 카드의 **설치** |
| Git 저장소 | *직접 만들기* 아래에 `https://` 주소를 붙여넣고 **Git에서 설치** |
| 폴더 | **폴더에서 설치…** 가 `~/.agentty/plugins/`로 복사합니다 |
| 편집 중인 폴더 | **개발용 폴더 연결…** 은 그 자리에서 실행하며, 삭제해도 연결만 해제됩니다 |

플러그인 폴더를 `~/.agentty/plugins/`에 직접 복사한 뒤 **새로 고침**을 눌러도 됩니다.

## 무엇을 신뢰하게 되는가

설치 전에 카드의 **권한** 아래에 그 플러그인이 할 수 있는 일이 완전한 문장으로 표시됩니다. HTTP 요청 보내기, 에이전트 세션 시작하기, 터미널에 입력하기, AI 대화 읽기, 워크스페이스 보기입니다.

**정보 → 실행 방식**에는 그 플러그인이 전혀 다른 두 가지 중 무엇인지가 표시됩니다.

| | |
|---|---|
| **WebAssembly** | Agentty가 모듈을 직접 실행합니다. 자기 파일도, 프로세스도, 네트워크도 없고, **어떻게 작성했든** 저 권한이 허용한 것만 건드립니다. |
| **프로그램** (`node`, `python`, 실행 파일) | 이용자 권한으로 실행되며, 이용자가 실행하는 다른 프로그램과 같은 접근 권한을 가집니다. 권한은 Agentty를 통한 동작만 통제하고, 프로그램 자체는 아무것도 통제하지 않습니다. |

> [!IMPORTANT]
> 프로그램 플러그인은 제작자를 신뢰할 때만 설치하세요. 마켓플레이스에 있는 것은 모두 전자이며, 목록에서 바이너리를 받아 설치해도 되는 이유가 바로 그것입니다.

전체 구조는 [플러그인 권한](/docs/plugin-permissions)에 있습니다.

## 마켓플레이스

**플러그인 → 마켓플레이스**는 [Agentty-Marketplace](https://github.com/empty-user77/Agentty-Marketplace)가 제공하는 목록을 보여줍니다. 플러그인은 풀 리퀘스트로 추가되고, 등록되는 것은 **소스가 공개된 WebAssembly 모듈**뿐입니다. Agentty 자체 플러그인도 같은 조건으로 그곳에 있습니다. 애플리케이션에 내장된 것은 없습니다.

설치할 때는 이렇게 됩니다.

1. Agentty가 HTTPS로 목록을 읽고 모든 항목을 여기서 다시 검사합니다. id, 문구, 권한, 모듈이 오는 호스트까지요. 검사를 통과하지 못한 항목은 표시되는 대신 목록에서 빠집니다.
2. 카드가 무엇인지, 소스가 어디인지, 라이선스, 모듈 크기와 체크섬, 그리고 무엇을 할 수 있는지를 보여줍니다.
3. **설치**를 누르면 Agentty가 모듈을 내려받아 그 체크섬과 대조합니다. **일치하기 전에는 플러그인 폴더에 아무것도 들어가지 않습니다.**

항목에는 그 모듈이 어느 플러그인 프로토콜을 대상으로 했는지도 적혀 있습니다. 더 낮은 버전만 아는 Agentty는 플러그인을 목록에 보여주되, 설치를 제안하는 대신 최신 Agentty가 필요하다고 알립니다.

혼자 쓰는 플러그인은 그 목록을 거칠 필요가 없습니다. **폴더에서 설치…** 와 **Git에서 설치**는 무엇이든 받습니다.

## 사용하기

- **패널** — 패널이 있는 플러그인은 버튼이 생깁니다. 터미널 위 탭 영역, 왼쪽 가장자리의 액티비티 바, 또는 아래쪽 상태 바 중 플러그인이 고른 자리입니다. 클릭하면 패널이 열리고, 다시 클릭하면 닫힙니다. 패널 헤더의 ↻는 플러그인을 재시작하고, 톱니바퀴는 플러그인 페이지를 엽니다.
- **명령 팔레트** — ⇧⌘P의 *플러그인* 항목에 모든 플러그인 명령이 나열됩니다.

### 패널이 열리는 자리

패널의 레이아웃 버튼으로 열리는 방식을 바꿀 수 있고, 그 선택은 유지됩니다.

| | |
|---|---|
| **도킹** | 터미널 옆에 붙고, 터미널이 자리를 비켜 줍니다 |
| **떠 있기** | 창 오른쪽 가장자리에 떠 있고, 다른 것은 움직이지 않습니다 |
| **독립 창** | 별도의 창. 이동과 크기 조절이 가능합니다 |
| **전체** | 터미널과 페이지가 쓰는 영역 전체 |

도킹된 패널이 나머지 창을 짓누를 만큼 커지지는 않습니다. 도킹 가능한 범위를 넘겨 끌면 떠 있는 패널이 됩니다.

### "보낼 곳…" 다이얼로그

플러그인이나 다른 앱의 링크가 프롬프트를 보내면, Agentty는 무엇이 전송되는지 보여주고 선택하게 합니다.

- **Claude Code / Codex / 터미널**
- **새 워크스페이스**(폴더 변경 가능), 현재 워크스페이스의 **새 탭**, 또는 **열려 있는 워크스페이스** 중 하나 — 그곳의 유휴 에이전트가 받고, 없으면 새 에이전트 탭이 열립니다
- **바로 전송**하거나, 체크를 해제해 입력만 되고 Enter는 누르지 않게 할 수 있습니다

터미널에는 입력만 됩니다. 이 경로로 보낸 프롬프트에는 Enter가 눌리지 않습니다. **보내기**를 누르기 전에는 아무것도 전송되지 않습니다.

`terminal.write`는 다른 물건입니다. 이 권한을 가진 플러그인은 열려 있는 터미널에 입력하고 **Enter까지 누릅니다**. 셸이라면 그 명령이 실행됩니다. 그 앞에는 아무 다이얼로그도 없고, 카드가 이 권한을 따로 이름 붙여 보여주는 이유가 그것입니다.

## 다른 앱에서 오는 링크

다른 앱은 `agentty://` 링크로 Agentty에 작업을 넘길 수 있습니다. Cosmica의 "Agentty에서 계속하기"가 그 예입니다.

| 링크 | 동작 |
|---|---|
| `agentty://plugin/<id>/<path>?key=value` | 플러그인 `<id>`를 시작하고 URL 핸들러를 호출 |
| `agentty://prompt?text=…&title=…&agent=…&cwd=…` | 해당 텍스트로 **보낼 곳…**을 엽니다 (`file=`로 절대 경로의 `.md`·`.txt` 첨부) |
| `agentty://plugins/<id>` | 플러그인 페이지의 해당 플러그인을 엽니다 |

링크가 필요로 하는 내장 플러그인이 아직 없으면 Agentty가 설치를 제안하고 이어서 링크를 처리합니다. 이 경로로 들어온 프롬프트는 언제나 **보낼 곳…**을 거칩니다.

> [!NOTE]
> 링크는 설치된 애플리케이션에서 동작합니다. 개발용으로 실행한 빌드는 운영체제에 `agentty://` 처리기로 등록되지 않습니다.

## Cosmica

[Cosmica](https://www.cosmica.ink/)는 노트 앱입니다. 플러그인이 Agentty에 기본 포함되어 있으며, Cosmica가 설치돼 있으면 *추천*으로 표시됩니다. Cosmica 설정에서 노트 폴더와 로컬 포트만 읽습니다.

1. **플러그인 → 설치**를 Cosmica 카드에서 누르고, 탭 영역에서 패널을 엽니다.
2. **노트 → 프롬프트** — 노트를 검색해 포커스된 터미널에 넣거나, 원하는 곳에서 이어갑니다.
3. **Cosmica에서** — 노트를 우클릭 → **Agentty에서 계속하기**. 노트가 먼저 저장되고 Agentty에서 **보낼 곳…**이 열립니다.
4. **세션 → Cosmica** — Claude Code나 Codex 페인이 포커스된 상태에서 **AI 요약 저장**을 누르면, 에이전트가 목표·수행 내용·변경된 파일·결정·다음 단계를 정리한 요약을 노트의 `Agentty/`에 작성합니다. **대화 로그 저장**은 AI에게 묻지 않고 원본 대화를 저장합니다.

작업 중인 에이전트는 방해하지 않습니다. 턴이 끝난 뒤 다시 시도하세요. Cosmica가 실행 중이면 로컬 API를 통해 저장되어 즉시 색인되고, 아니면 파일로 기록된 뒤 다음 실행 때 반영됩니다.

## 문제가 생기면

| 증상 | 조치 |
|---|---|
| "Node.js를 찾을 수 없음" | JavaScript 플러그인은 로그인 셸의 `PATH`에 Node.js 18 이상이 필요합니다. WebAssembly 플러그인은 설치할 것이 없습니다 |
| 마켓플레이스 설치가 거부됨 | 모듈이 목록의 체크섬과 일치하지 않았습니다. 아무것도 기록되지 않았으니 제작자에게 알리세요 |
| 카드에 최신 Agentty가 필요하다고 표시됨 | 이 버전이 모르는 플러그인 프로토콜로 만들어진 플러그인입니다. Agentty를 업데이트하세요 |
| 카드에 오류로 중단됐다고 표시됨 | 카드의 **로그**를 열어 확인하고, 코드를 고친 뒤 **재시작** |
| 복사해 넣은 플러그인이 보이지 않음 | **새로 고침**을 누르고, 폴더 이름이 `agentty-plugin.json`의 `id`와 같은지 확인 |
| 링크가 아무 반응이 없음 | 설치된 애플리케이션을 쓰고, 링크가 지정한 플러그인이 설치·활성화돼 있는지 확인 |
| 업데이트 후 동작이 이상함 | **재시작**하거나 **비활성화**하고 제작자에게 문제를 알리세요 |

## 파일 위치

| 경로 | 용도 |
|---|---|
| `~/.agentty/plugins/<id>/` | 플러그인 본체 |
| `~/.agentty/plugins/state.json` | 활성화 상태와 개발용 연결 위치 |
| `~/.agentty/plugin-data/<id>/` | 플러그인의 설정과 캐시 |
| `~/.agentty/plugins/.sdk/` | **개발자 가이드**가 풀어 놓는 SDK와 문서 |
| `~/.agentty/prompts/` | 파일로 전달되는 긴 프롬프트 |

삭제하면 플러그인은 제거되지만 데이터 폴더는 직접 지울 때까지 남습니다.
