description: 다섯 가지 권한, 권한이 없을 때 플러그인이 보는 것, 그리고 WebAssembly 플러그인이 프로그램과 전혀 다른 이유.
---

플러그인이 할 수 있는 일은 `agentty-plugin.json`에 미리 선언되고, 설치 전에 이용자에게 표시됩니다. 권한 없이 호출하면 `-32001` 오류로 실패합니다.

## 다섯 가지 권한

| 권한 | 이용자에게 표시되는 문구 | 메서드 |
|---|---|---|
| `net.request` | 지정한 주소로 HTTP 요청을 보냅니다 | `net/fetch` |
| `prompt.inject` | 에이전트 세션 시작·프롬프트 전송 | `prompt/inject` |
| `terminal.write` | 터미널에 입력하고 Enter까지 | `terminal/send` |
| `session.read` | Agentty에 열린 AI 세션의 대화를 읽습니다 | `session/get` |
| `workspace.read` | 열린 워크스페이스·탭·폴더와 에이전트 상태를 봅니다 | `workspace/list`, `host/revealPath`, `pane/status` |

플러그인 자신의 저장소와 패널에는 권한이 필요 없습니다. `storage/get`·`storage/set`·`storage/keys`는 플러그인 자기 폴더(`<데이터 폴더>/plugin-data/<id>/storage.json`, `0600`으로 생성)이며 키 64개, 총 1MB까지입니다. WebAssembly 플러그인에는 자기 파일이 없으므로 무언가를 기억하는 수단은 이것뿐입니다.

> [!IMPORTANT]
> `net.request`와 `session.read`나 `workspace.read`를 함께 가지면, 플러그인이 여러분의 작업을 읽어서 어딘가로 보낼 수 있다는 뜻입니다. 둘 다 요청하는 플러그인은 설명에 그 이유를 분명히 적어야 하고, 그러지 않은 것은 마켓플레이스가 거부합니다.

## 두 종류의 플러그인

가장 중요한 구분이고, 플러그인 페이지의 **정보 → 실행 방식**에 표시됩니다.

| | |
|---|---|
| **`wasm`** | Agentty가 모듈을 직접 실행합니다. 파일도, 소켓도, 환경 변수도, 프로세스도 없습니다. **어떻게 작성했든** 프로토콜이 허용한 것만 건드립니다. |
| **`node`, `python`, `executable`** | 이용자 권한으로 실행되는 프로그램입니다. 이용자가 실행하는 다른 프로그램과 같은 파일·네트워크 접근 권한을 가집니다. 위 권한은 프로토콜을 통한 동작만 통제하며, 프로그램 자체는 아무것도 통제하지 않습니다. |

그래서 권한 목록의 의미가 둘 사이에서 달라집니다. WebAssembly 플러그인에서는 그 플러그인이 할 수 있는 일의 전부입니다. 프로그램에서는 *Agentty를 통해* 할 수 있는 일의 전부일 뿐입니다. 파일은 원래부터 직접 열 수 있었으니까요.

프로그램 플러그인은 제작자를 신뢰할 때만 설치하세요. [마켓플레이스](/docs/plugin-publishing)가 소스가 공개된 WebAssembly 모듈만 다루는 이유가 정확히 이것입니다.

## 권한이 없을 때 플러그인이 보는 것

컨텍스트는 선언한 권한에 따라 걸러집니다. `workspace.read`가 없으면 폴더와 제목 필드가 제거되고, `session.read`가 없으면 세션 id가 제거됩니다. 남는 것은 id, `kind`, `tool`, `status`, `running`, 언어입니다. 어느 페인이 포커스됐고 작업 중인지는 알 수 있지만, 어디서 무엇을 하는지는 알 수 없습니다.

```json
{
  "pane": { "id": 12, "kind": "claude", "tool": "claude", "status": "working", "running": true },
  "language": "ko"
}
```

## 프롬프트가 어디로 가고, 누가 골랐는가

다이얼로그는 경계가 아닙니다. 이 점은 분명히 해 둘 필요가 있습니다. `prompt.inject`는 플러그인이 **묻지 않고 자체 에이전트 세션을 열어 텍스트를 보낼 수 있게** 합니다. 의도된 설계입니다. [AgentOS](/docs/plugin-agentos)는 자기가 시작한 세션으로 단계를 진행하는 것이 일의 전부인 플러그인이고, 다이얼로그를 거쳐서는 그렇게 할 수 없습니다.

플러그인이 선택을 이용자에게 넘길 **수도** 있습니다. `target: "ask"`로 호출하면 **보낼 곳…**이 열립니다. 이용자가 텍스트를 보고 에이전트와 목적지를 고르며, **보내기**를 누르기 전에는 아무 일도 일어나지 않습니다. 그 외의 target — `newTab`, `newWorkspace`, `active`, `pane`, `workspace` — 은 모두 이 다이얼로그를 건너뜁니다. 그러니 외부에서 온 것을 받아 동작하는 플러그인은 항상 `ask`를 써야 하고, 링크로 실행된 플러그인에는 선택권이 없습니다. 무엇을 요청했든 Agentty가 다이얼로그로 돌립니다.

두 호출은 Enter에서 갈리고, 그 차이가 `terminal.write`의 전부입니다.

- `injectPrompt`는 터미널에서 Enter를 대신 누르지 않습니다. 텍스트를 입력해 두고 이용자에게 맡깁니다.
- `sendToTerminal`은 다른 물건이고, Enter를 **누릅니다**. 셸이라면 그 명령이 실행됩니다.

## 링크는 신뢰하지 않습니다

`agentty://` 링크는 웹페이지를 포함해 어디서든 올 수 있습니다. 링크가 플러그인에 한 번 도달하면, 그 플러그인이 실행되는 내내 Agentty는

- 그 플러그인의 `prompt/inject`를 target과 무관하게 **보낼 곳…**으로 돌리고 Enter도 누르지 않으며,
- `terminal/send`를 아예 거부합니다.

플러그인이 실행되는 동안에는 무엇으로도 풀리지 않습니다. 링크가 연 패널에서 클릭하는 것은 터미널에 입력해도 된다는 동의가 아니고, 기다리는 것도 마찬가지입니다. 이용자가 클릭하는 만큼이나 플러그인도 쉽게 기다릴 수 있으니까요. **푸는 것은 플러그인 재시작뿐입니다.**

링크가 도달한 플러그인이 Agentty 밖으로 할 수 있는 일은 `host/openUrl` 하나뿐이고, 한 번에 주소 하나입니다. Agentty는 좋은 주소와 나쁜 주소를 구분할 수 없으므로 그 부분은 작성자의 몫입니다. 링크가 건넨 것은 낯선 사람이 준 텍스트로 취급하고, 거기서 받은 주소를 확인 없이 열지 마세요.

> [!IMPORTANT]
> 링크를 처리하는 플러그인이라면 모든 파라미터를 검증하세요. Cosmica 플러그인은 Cosmica 노트 폴더 안의 `.md` 파일만 열고, 폴더 밖 경로는 거부합니다.

## `net.request`로 할 수 있는 일

`net/fetch`는 플러그인이 네트워크에 닿는 유일한 방법이고, Agentty가 범위를 제한합니다.

| | |
|---|---|
| 메서드 | `http`·`https`에서 `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS` |
| 헤더 | 최대 32개. `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Upgrade`, `Expect`는 불가, 줄바꿈이 든 것도 불가 |
| 요청 본문 | 1MB |
| 응답 | 4MB까지 보관 (`truncated`가 더 왔는지 알려 줍니다) |
| 타임아웃 | 기본 15초, 최대 60초 |
| 동시 요청 | 플러그인당 4개 |

**요청에는 여러분의 것이 아무것도 실리지 않습니다.** 쿠키도, 저장된 자격 증명도 없고, 플러그인이 직접 넣은 것만 갑니다. 호출마다 URL을 가린 채 플러그인 로그에 기록됩니다.

리다이렉트는 3번까지 따라가며, 그 주소도 처음 요청과 똑같은 검사를 거칩니다. `http`나 `https`여야 하고, 링크로컬이나 메타데이터 주소가 아니어야 합니다. 그러지 않으면 서버가 `302 Location: http://169.254.169.254/…`로 응답해 검사를 우회할 수 있습니다. `Authorization`이나 `Cookie` 헤더는 다른 호스트로 넘어가지 않고, 리다이렉트된 `POST`·`PUT`·`PATCH`는 응답이 `307`이나 `308`이 아닌 한 본문 없는 `GET`이 됩니다.

## 레이트 리밋과 폭주 방지

Agentty는 실수든 아니든 잘못 동작하는 플러그인으로부터 자신을 보호합니다.

| 제한 | 동작 |
|---|---|
| 패널 다시 그리기 | 최소 50ms 간격 |
| 알림 | 최소 700ms 간격. 초과분은 정상 응답 후 폐기. 메시지는 300자에서 잘립니다 |
| URL 열기 | 최소 700ms 간격. `host/openUrl`도 알림과 같은 방식으로 제한됩니다 |
| 메시지 | 초당 240건을 넘으면 폭주로 간주해 플러그인 중단 |
| UI 트리 | 요소 2,000개, 깊이 12단계, 문자열당 20,000자. `choice`의 옵션과 리스트 항목의 버튼도 각각 요소로 셉니다 |
| 줄 길이 | stdout·stderr 각 16MB |
| WebAssembly | 모듈 64MB, 메모리 64MB, 메시지당 16MB, 하나를 처리하는 동안 메시지 256개 — `send`와 `log`를 합쳐서 |

## 요청한 권한에 값하는 플러그인 만들기

- **쓰는 권한만 요청하세요.** 모든 권한이 이용자에게 표시되며, 쓰지 않는 권한은 신뢰만 깎아먹습니다.
- **자격 증명을 읽거나 보내지 마세요.** 다른 앱의 설정을 읽는다면 필요한 필드만 가져오세요. Cosmica 플러그인은 `notes.path`와 포트만 읽습니다.
- **데이터는 플러그인 자신의 저장소에 두세요.** 다른 앱이 읽는 파일은 조심해서 만들고, 이용자의 파일을 요청 없이 덮어쓰지 마세요.
- **`127.0.0.1`하고만 통신하세요.** 이용자가 직접 다른 곳을 설정한 경우가 아니라면요.
- **입력 전에 `pane.status`를 확인하세요.** `working`, `permission`, `question` 상태는 방해하면 안 됩니다.
- **외부에서 온 것은 무엇이든 검증하세요.** 링크든 파일이든 서버 응답이든 그대로 믿고 동작하지 마세요.

## 남의 플러그인을 설치하기 전에

- 카드의 권한을 읽으세요. 노트 플러그인이 `terminal.write`를 요구한다면 그 이유가 설명돼 있어야 합니다.
- **실행 방식**을 확인하세요. WebAssembly 모듈은 프로그램보다 훨씬 작은 신뢰만 요구합니다.
- 소스를 읽을 수 있는 플러그인을 선호하세요. 카드의 링크가 대개 저장소를 가리킵니다.
- 설치 후 **로그**를 보면 플러그인이 실제로 무엇을 하는지 확인할 수 있습니다.
- **비활성화**는 즉시 적용되고, **삭제**는 플러그인을 제거합니다. 데이터 폴더는 직접 지울 때까지 남습니다.
