---
title: Launch 배포
description: 컴퓨터의 폴더를 실제 URL로 — GitHub, Vercel, 필요하면 Supabase까지.
---

Launch는 프로젝트를 공개하는 기본 제공 플러그인입니다. **GitHub 로그인 → 저장소에 저장 → Vercel 로그인 → 프로젝트가 쓰는 경우 데이터베이스 → 환경 변수 → 게시** 순으로, 한 번에 한 단계씩, 기본 버튼 하나씩, 토큰을 손으로 복사하는 일 없이 진행합니다.

페인 위의 로켓 버튼이나 명령 팔레트(**Launch: Publish this project to the web**)에서 엽니다.

## 단계

1. **프로젝트 확인** — 활성 페인의 폴더를 보고 프레임워크를 판별합니다(Next.js, Vite, Astro, 정적 사이트 등).
2. **도구** — GitHub CLI와 Vercel CLI가 필요합니다. `PATH`에 없으면 Launch가 자체 데이터 폴더에 설치합니다. 시스템 전역에는 아무것도 설치하지 않습니다.
3. **GitHub 로그인** — GitHub CLI에 이미 로그인되어 있거나, 이 컴퓨터에 저장소로 푸시할 수 있는 SSH 키가 있으면 건너뜁니다. 아니면 CLI의 브라우저 로그인을 대신 실행하고, 일회용 코드를 크게 표시해 클립보드에 복사합니다. 로그인은 저장소를 새로 만들어야 할 때만 요청합니다.
4. **GitHub에 저장** — 전체를 커밋하고 새 비공개 저장소를 만듭니다. 공개는 토글입니다.
5. **Vercel 로그인** — 같은 방식입니다.
6. **데이터베이스** — Supabase를 쓰는 프로젝트이거나 **데이터베이스 연결**을 누른 경우에만 진행합니다.
7. **환경 변수** — `.env` 파일이 있으면 그 **이름만**(값은 절대 표시하지 않습니다) 나열하고 각각 토글을 제공합니다. 로컬에서만 의미 있는 값은 꺼진 상태로 시작합니다.
8. **게시** — 프로덕션으로 배포하며 실시간 로그를 보여주고, 이후의 push가 자동 배포되도록 저장소를 Vercel에 연결합니다.

## 웹 프로젝트가 아닌 폴더에서

Launch가 대신 **대시보드**로 열립니다. 설치된 명령줄 도구, GitHub·Vercel 로그인 상태, Vercel 계정의 모든 프로젝트와 각 프로젝트가 배포하는 저장소를 보여줍니다. 배포할 것이 생기기 전에 두 로그인을 여기서 미리 해 둘 수 있습니다. 대시보드와 배포 단계는 탭으로 오가며, 지금 보고 있는 터미널의 폴더가 어느 쪽으로 열릴지 정합니다.

## 하지 않는 일

- 첫 커밋 전에 env 파일, 키 파일, 로컬 도구 상태를 `.gitignore`에 추가하며, **실제 env 파일이나 키 파일이 추적 중이거나 스테이지되어 있으면 저장을 거부합니다.**
- 이미 리모트가 있는 프로젝트는 그 리모트가 어디를 가리키는지 보여주고, 푸시하기 전에 한 번 확인합니다.
- `.vercelignore`를 먼저 작성하므로 아이디어 노트, `.claude/`, 마이그레이션, env 파일은 업로드되지 않습니다.

## 누구의 계정인가

이용자 본인의 계정입니다. Launch는 각 서비스의 공식 도구와 로그인 페이지를 통해 로그인하며, 토큰은 이용자의 컴퓨터에서 그 도구가 보관합니다. 게시하는 내용은 각 회사의 약관에 따라 GitHub, Vercel, Supabase로 전달되며, 당사에는 아무것도 도달하지 않습니다.

실패한 단계는 짧은 메시지와 함께 **다시 시도**, 그리고 문제를 에이전트에게 넘기는 선택지를 보여줍니다.
