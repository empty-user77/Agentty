---
title: チャットワークスペース
description: リードエージェント 1 人とチャットし、仕事を任された最大 4 人のワーカーが下で動く様子を見る。
---

チャットワークスペースは、上に会話を、下にエージェントのチームを置きます。チャットで話す相手は **リードエージェント**（Claude Code）1 人です。リードは作業を計画し、分けた仕事を **ワーカー** に任せます。各ワーカーはチャットの下のグリッドでそれぞれのターミナルで動くので、チーム全体の様子を一度に見られます。

## 開き方

- スタートページ（または **新しいワークスペース**）で **チャット · チーム** を選び、プロジェクトフォルダを選びます。
- またはタブ横の **+** メニューから **新しいチャットワークスペース** を選びます。

リードはプロジェクトフォルダそのもので作業します。各ワーカーはプロジェクトの既定ブランチから作った新しいブランチの専用 git ワークツリーで作業するので、互いに同じファイルを編集しません。

## 仕組み

1. チャットに書きます。**Enter** で送信、**Shift+Enter** で改行です。
2. 小さなことはリード自身が答えます。大きな作業は計画を立て、`agentty tasks` でワーカーを起動します。チャットワークスペースでは通常の確認ダイアログなしにすぐ始まります。チャットを開いたことが同意です。
3. ワーカーはチャットの下のグリッドに 1 行 2 つずつ、同時に最大 **4** 個まで表示されます。4 つの枠が埋まっていると、最も早く終わったワーカーが閉じて次のワーカーに場所を譲ります。そのブランチとセッションは残るので、セッション一覧から再開できます。
4. ワーカーがターンを終えると、Agentty がリードに短い報告を送ります。報告にはワーカー名、ブランチ、フォルダ、最後の返答が入っています。リードは作業を確認してチャットで伝えるか、ワーカーに追加の指示を送ります。

チャットの上のバーにはリードの状態と、ワーカーごとのチップが表示されます。チップをクリックするとそのワーカーのターミナルに移動します。ワーカーが承認や回答を待っているときは、チャットにも表示されます。

## リードのターミナル

チャットは実際の Claude Code セッションを表示する画面です。バーの **ターミナル** でリードのターミナルを表示し、**チャット** で戻ります。ターミナルでしか答えられないときは、ターミナルが自動で表示されます。

- 初回起動時のフォルダの信頼確認やサインイン
- リードのツール承認や質問

そこで答えるとチャットに戻ります。その間に届いたワーカーの報告は、リードが受け取れるようになるまで待ちます。

## リードが使うコマンド

| コマンド | 内容 |
|---|---|
| `agentty tasks --plan <plan.json>` / `--title … --prompt-file …` | ワーカーを起動（ここではダイアログなし） |
| `agentty tasks status` | ワーカーの一覧とそれぞれの状態 |
| `agentty tasks send --to <名前> --prompt <内容>` | ワーカーに追加のメッセージを送る |

`status` と `send` はチャットワークスペースのリードだけが、自分のワーカーに対してのみ使えます。

## 知っておくと便利なこと

- ワーカーは自分のブランチにコミットします。プッシュやプルリクエストの作成は、リードに頼んだときだけ行います。リードがブランチをマージするのは、頼まれたとき、またはマージを含む計画が承認されたときだけです。
- ワーカーはそれぞれが完全なエージェントセッションなので、4 人同時に動かすと 1 人のときよりプランの上限を早く消費します。
- チャットとグリッドの境界線をドラッグすると、どちらかを広げられます。レイアウトはワークスペースと一緒に保存されます。
- 設定で **エージェントが並列タスクを開始できる** をオフにすると、チャットのリードもワーカーを起動できなくなります。
