title: チャットワークスペース
description: リードエージェント 1 人とチャットし、仕事を任された最大 4 人のワーカーとレビュアーが下で動く様子を見る。
---

チャットワークスペースは、上に会話を、下にエージェントのチームを置きます。チャットで話す相手は **リードエージェント**（Claude Code）1 人です。リードは作業を計画して **ワーカー** に分けて任せ、その成果を **レビュアー** に確認させることができます。全員がチャットの下のグリッドでそれぞれのターミナルで動くので、チーム全体の様子を一度に見られます。

## 開き方

- スタートページ（または **新しいワークスペース**）で **チャット · チーム** を選び、プロジェクトフォルダを選びます。
- またはタブ横の **+** メニューから **新しいチャットワークスペース** を選びます。

## チャットのブランチ

git リポジトリでは、チャットごとに専用のブランチ（`agentty/chat-…`、チャットのバーに表示）が作られ、リードはそのブランチのワークツリーで作業します。プロジェクトフォルダには触れません。

- 各ワーカーは新しいブランチのワークツリーを受け取ります。そのブランチは **チャットのブランチの最新コミット** から始まるので、リードがすでにマージした作業を次のワーカーが引き継げます。
- リードは作業を確認してから、ワーカーのブランチをチャットのブランチにマージします。
- 結果がプロジェクトフォルダに届くのは、求めたときだけです。リモートがあればリードがプルリクエストを開き、なければプロジェクトフォルダに未コミットの変更がないときにそこへマージします。

コミットが 1 つもないリポジトリには分岐元がありません。その場合リードはプロジェクトフォルダで作業し、リードが最初のコミットを作った後、ワーカーは既定ブランチから始まります。

## 仕組み

1. チャットに書きます。**Enter** で送信、**Shift+Enter** で改行です。
2. 小さなことはリード自身が答えます。大きな作業は計画を立て、`agentty tasks` でワーカーを起動します。チャットワークスペースでは通常の確認ダイアログなしにすぐ始まります。チャットを開いたことが同意です。
3. ワーカーはチャットの下のグリッドに 1 行 2 つずつ、レビュアーを含めて同時に最大 **4** 個まで表示されます。4 つの枠が埋まっていると、最も早く終わったものが閉じて次に場所を譲ります。そのブランチとセッションは残るので、セッション一覧から再開できます。
4. ワーカーがターンを終えると、Agentty がリードに短い報告を送ります。報告にはワーカー名、ブランチ、フォルダ、最後の返答が入っています。リードは作業を確認してマージするか、チャットで伝えるか、ワーカーに追加の指示を送ります。

チャットの上のバーには、リードの状態、チャットのブランチ、ワーカーごとのチップが表示されます。チップをクリックするとそのワーカーのターミナルに移動します。ワーカーが承認や回答を待っているときは、チャットにも表示されます。

## ワーカーとレビュアー

チャットのバーにある 2 つのボタンで、誰が作業するかを選びます。

| ボタン | 選択肢 | 決めること |
|---|---|---|
| **ワーカー** | Claude · Codex | リードがタスクで指定しなかったときに新しいワーカーが使うエージェント |
| **レビュアー** | オフ · Claude · Codex | マージ前に各ワーカーの作業をレビューするようリードに求めるか、どのエージェントで行うか |

**レビュアー** はワーカーのフォルダで起動し、チャットのブランチとの差分を読みます。テストは実行でき、何も変更しないよう指示されます。Codex は読み取り専用サンドボックスで動き、Claude Code は編集ツールなしで動きます（シェルからは書き込めるため、その場合は指示に頼ります）。最後は `Verdict: approve` か `Verdict: changes needed` で終わり、その報告はワーカーの報告と同じようにリードに届きます。レビュアーがオフでもリードはレビュアーを起動でき、そのときもボタンで選んだエージェントが使われます。

選択はチャットと一緒に保存されます。

## リードのターミナル

チャットは実際の Claude Code セッションを表示する画面です。バーの **ターミナル** でリードのターミナルを表示し、**チャット** で戻ります。ターミナルでしか答えられないときは、ターミナルが自動で表示されます。

- 初回起動時のフォルダの信頼確認やサインイン
- リードのツール承認や質問

そこで答えるとチャットに戻ります。その間に届いたメッセージは、リードが受け取れるようになるまで待ちます。エージェントの画面に承認や質問が表示されている間、Agentty は何も入力しません。

## リードが使うコマンド

| コマンド | 内容 |
|---|---|
| `agentty tasks --plan <plan.json>` / `--title … --prompt-file …` | ワーカーを起動（ここではダイアログなし） |
| `agentty tasks status` | ワーカーの一覧、それぞれの状態、チャットの選択 |
| `agentty tasks send --to <名前> --prompt <内容>` | ワーカーに追加のメッセージを送る |
| `agentty tasks result --to <名前>` | ワーカーの最後の返答をもう一度表示 |
| `agentty tasks stop --to <名前>` | ワーカーを閉じる（ブランチとセッションは残る） |
| `agentty tasks review --worker <名前> [--prompt <観点>] [--agent claude\|codex]` | ワーカーの作業のレビュアーを起動 |

これらのコマンドはチャットワークスペースのリードだけが、自分のワーカーに対してのみ使えます。

## 知っておくと便利なこと

- ワーカーは自分のブランチにコミットします。プッシュやプルリクエストの作成は、リードに頼んだときだけ行います。
- ワーカーとレビュアーはそれぞれが完全なエージェントセッションなので、4 人同時に動かすと 1 人のときよりプランの上限を早く消費します。
- チャットとグリッドの境界線をドラッグすると、どちらかを広げられます。レイアウトはワークスペースと一緒に保存されます。
- 設定で **エージェントが並列タスクを開始できる** をオフにすると、チャットのリードもワーカーを起動できなくなります。
- チャットのブランチ機能より前に開いたチャットは、引き続きプロジェクトフォルダで作業します。
