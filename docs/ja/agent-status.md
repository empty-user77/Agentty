---
title: エージェントの状態
description: Agentty が各エージェントの状態を知る仕組みと、その伝え方。
---

Agentty は起動したエージェントを見守り、それぞれが作業中か、終わったか、こちらを待っているかを示します。

## 状態が現れる場所

- **サイドバー** — 各ワークスペースの行が、その中のエージェントの状態を表します。
- **ペインの枠** — エージェントが質問したり許可を求めたりすると光り、クリックするまで続きます。
- **エージェントペイン上のステータスバー** — モデル、コンテキストウィンドウ、利用上限、ブランチ、フォルダ。
- **通知** — エージェントが終わったとき、答えを待っているとき。クリックするとそのペインが開きます。
- **⇧⌘U** — 最新の未読ペインへ移動。
- **ミニモードとメニューバー** — ウィンドウを前面に置かずに状態を把握。

## コンテキストウィンドウ

ステータスバーのコンテキストの数値はメーターです。クリックすると**コンテキストメモリ**パネルが開き、システム・ツール、メモリファイル、スキル、要約、会話に分けて示し、前回の圧縮以降に読み書きしたファイルも教えてくれます。

ウィンドウの大きさはエージェント自身が報告した値を使います（Claude Code はステータスライン、Codex はセッションログ）。モデル名から推測することはありません。報告される前は、メーターは使用中のトークン数だけを表示し、割合は表示しません。

パネルにはその数値の横に**圧縮**ボタンがあります。数値にかかわらずエージェント自身の圧縮コマンド（Claude Code・Codex）を実行するので、長い作業のあとではなく前に余裕をつくれます。ステータスバー自体の圧縮ボタンは、メーターがオレンジに変わる 70% から現れます。

## 状態の種類

| 状態 | 意味 |
|---|---|
| 作業中 | ツールを実行している |
| 思考中 | ターンが開いており、ツール呼び出しの合間 |
| 入力待ち | 質問したか、許可を求めた |
| 完了 | ターンが終わった |
| アイドル | 実行中のものがない |

## 仕組み

Agentty はペインを起動するときにコマンドラインで状態フックを渡します。エージェントは、利用者のアカウントだけが到達できるローカル専用のソケットに状態を報告します。プロジェクトやエージェント自身の設定ファイルには何も書き込みません。

## 通知

**設定 → 通知**で決めます。

- エージェントが終わったとき、入力が必要なときのシステム通知。
- Agentty が前面にあるときも通知するかどうか。
- 質問と許可要求は、そのペインを見ていない限り必ず通知されます。
- エージェントが同じ質問を複数回報告しても、質問ひとつにつき通知は 1 回です。回答したあとの新しい質問は、あらためて通知されます。

### 通知から許可・拒否する

Claude Code や Codex の許可要求の通知には、要求の内容（ツールと、コマンドならその内容）と **許可**・**拒否** ボタンが付きます。macOS の通知でもミニウィンドウの吹き出しでも同じです。許可は「Yes」で一度だけ許可し、拒否は「No」（Esc）で答えて、エージェントは別の指示を待ちます。どちらも Agentty を前面に出しません。「今後は確認しない」はターミナルでのみ選べます。

Agentty が答えを入力するのは、その要求が画面でまだ待っている間だけです。すでにターミナルで答えた場合やエージェントが先に進んだ場合は、入力せずにそのペインを開きます。macOS では、許可には Mac のロック解除が必要です。バナースタイルではボタンは通知にポインタを重ねたときに表示されます。システム設定 → 通知で Agentty を **通知パネル** スタイルにすると表示されたままになります。複数の答えから選ぶ質問はターミナルで答えます。
- 「前面」かどうかは、その瞬間に Agentty がアクティブなアプリかどうかで判断します。

### スマートフォンで受け取る

同じ画面で **Slack**、**Discord**、**Telegram** を接続すると、席を外していても質問が届きます。エージェントが自分を必要としたときだけ送るか、完了時にも送るか、そしてエージェントが何を尋ねたかを含めるかを選べます。

Slack と Discord はどちらの方式でも使えます。Webhook の URL を使うか、ボットトークンと書き込むチャンネルを指定します — Slack は `#general`・`general`・チャンネル ID、Discord はチャンネル ID を受け付けます。Telegram は常にボットで、書き込むチャットを指定します。

Webhook の URL とボットトークンは、設定ファイルではなく OS の資格情報ストアに保管されます。
