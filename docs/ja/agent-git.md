## git ページ

**⇧⌘G** で GitHub Desktop 風のページが開きます。

- リポジトリとブランチの切り替え
- **fetch**（⇧⌘T）、**pull**、**push**（⌘P）、**再読み込み**（⌘R）
- 差分をファイルごとに確認し、選んだものをステージしてコミット（⌘↩）
- 履歴の閲覧とブランチのマージ

Agentty は利用者自身の `git` を、その設定と認証情報のまま使います。すべてのコマンドは非対話で実行されるため、見えないプロンプトで止まることがありません。認証ヘルパーで処理できない push は、固まる代わりにメッセージを出して失敗します。

## ペインから直接

どのペインでもヘッダーのブランチ名をクリックすれば、ターミナルを離れずにブランチ切り替え、pull、push、名前のコピーができます。

一覧のブランチを右クリックすると、**このブランチに切り替え**、**名前を変更…**、**ここから新しいブランチ…**、**名前をコピー**、**ブランチを削除**が使えます。どこにもマージされていないコミットがあるブランチは、もう一度確認してからでないと削除されず、ダイアログでリモートのコピーも一緒に削除できます（**リモートの … も一緒に削除**）。**サーバー（リモート）から削除**は、確認のうえ全員分のリモートブランチを削除します。git はひとつのブランチを同時にひとつのフォルダでしか開けないため、別のフォルダがそのブランチを使っていて切り替えが拒否されたときは、黙って失敗する代わりに**そのフォルダを開く**を提案します。

### AI で解決

マージが競合で止まったとき、ブランチと上流ブランチが分岐していて pull できないとき、未解決の競合が残っているときは、メッセージに **AI で解決**が表示されます。リポジトリで Claude Code を開き、なければ Codex か、インストール済みの別のエージェントを開いて、競合解決の指示を渡します。エージェントがない場合は、リポジトリでターミナルだけを開きます。マージが進行中のあいだは、別のマージを始めません。

## セッションごとに 1 つのワークツリー

別のセッションがすでに作業しているプロジェクトで 2 つ目の AI セッションを開くと、Agentty がどこで始めるかを尋ねます。**新しいワークツリーを作成** は、プロジェクトの既定ブランチから切った新しいブランチの専用 git ワークツリーで起動し、2 つのエージェントが同じファイルを編集しないようにします。**既存のワークツリーを開く** は同じワークツリーで新しいセッションだけを始めます。1 つのブランチを 2 つのセッションで見たり一緒に作業したりしたいときに使います。ターミナルに `claude` や `codex` と入力したときも同じ質問が出ます。

- ワークツリーは `~/.agentty/worktrees/` の下に、`agentty/<名前>` ブランチで作られます。
- すべてのセッションを同じフォルダで動かしたいなら**設定 → 一般**でオフにします。

### 仕組み

Agentty は新しいブランチ `agentty/<名前>` で `git worktree add` を実行します。基準はプロジェクトフォルダが今チェックアウトしているブランチではなく、**既定ブランチ**です。そのため、あるセッションが別のセッションの未マージの作業の上に積み上がることがありません。

ツリーはプロジェクトの外、`~/.agentty/worktrees/<プロジェクト>-<パスのハッシュ>/<名前>/` に作られます。プロジェクトフォルダの中に置かないことが重要です。コードの複製がその中にあると、あらゆる検索、ファイル監視、ビルドがその複製まで辿ってしまいます。

Agentty が削除するのはそのフォルダ配下のツリーだけです。利用者が自分で作ったワークツリーは一覧に出るだけで、触りません。

## ファイルパネル

**⌥⌘B** はプロジェクトツリーをターミナルの横に置きます。プロジェクトの**すべてのワークツリー**と、それぞれで誰が作業し何が変わったかも示します。

ツリーをクリックすると、その中のファイルが表示されます。すでに作業中のセッションがあれば、そのターミナルへ移動します。

残りは右クリックメニューにあります。作業中のターミナルへ移動する、新しいターミナルを開く、ファイルマネージャーでフォルダを表示する、パスをコピーする、ツリーを削除する。フォルダを手で消してしまったツリーも、同じメニューから整理できます。

削除は必ず確認します。ダイアログがブランチ名と、何がなくなるのかを示します。ワークツリーとそのフォルダ、そして**ワークツリーとブランチを削除**を選んだ場合はローカルブランチもです。そのブランチをプッシュしたことがあれば、リモートでも削除するかを合わせて尋ねます。既定はオフで、ローカルブランチが実際に削除されたときにだけリモートも削除します。どちらの場合も、安全かどうかは git が決めます。未コミットの変更があるツリーは残り、他にないコミットを持つブランチも残ります。

タブがまだ作業中のツリーは削除されません。メニューから削除の項目そのものが消え、別の方法で消そうとしても、確認する代わりにその旨を伝えます。先にそのタブを閉じてください。

### パネルのワークツリー一覧

**ワークツリー**セクションには、ペインがあるリポジトリのワークツリーが並びます。ホームフォルダのようにプロジェクトが集まるフォルダでは、その下でワークツリーを持つすべてのプロジェクトをプロジェクトごとにまとめて表示し、各グループは折りたためます。最後に作業したプロジェクトが先頭で、その中ではプロジェクトフォルダ、続いてワークツリーが新しい順に並びます。各行には最後に作業した時刻（最後のコミット、または最新の未コミットの変更）が表示されます。フォルダはパネルを開いているあいだだけ調べ、セクションはドラッグでサイズを変えられます。再読み込みボタンでもう一度調べます。

ワークツリーがあると、**ファイル**ボタンが紫色になり、その数が表示されます。

ワークツリーをダブルクリックするか、右クリックして**このターミナルで開く**を選ぶと、そのシェルのまま続きを作業できます（先に確認します）。**整理してプロジェクトフォルダに戻る**は、ワークツリーを削除してターミナルをプロジェクトに戻します。ブランチがマージ済みで未コミットのものがなければすぐに実行し、そうでなければ何が失われるかをダイアログが正確に示します。エージェント、実行中のシェル、別のペインがそのツリーで作業している間は拒否されます。

シェルがいたワークツリーのフォルダが削除された場合は、なくなったフォルダではなくプロジェクトフォルダに移ります。

### 削除しても残るもの

ワークツリーと一緒にブランチが削除されるのは、既定ブランチがそのコミットをすべて持っているときだけです。既定ブランチにないコミットを持つブランチは、プッシュ済みでも残ります。[モニタリング](/docs/monitoring)の**ワークツリー管理**ページも同じです。無視されているビルドフォルダ（`build/`、`out/`、`dist/`、`.cache/`、`coverage/`）は中身のファイルで判断し、ファイルがあれば先に確認します。`target/` や `node_modules/` などはこれまでどおり削除されます。

## 並列タスク

エージェントに作業を分けるよう頼めます —「A と B と C を並行で」。エージェントが Agentty に要求し、一度確認すれば、各タスクがそれぞれの分割ペインと専用のワークツリーで始まります。

この要求は毎回確認を経ます。エージェントが勝手にペインを開くことはできません。

## ファイルエディタ

ファイルパネルでファイルをクリックすると、ターミナルの横で開きます。主要な言語のシンタックスハイライト、対で入力される括弧と引用符（対応する括弧は枠で表示）、行のコメントアウト **⌘/**、行の移動 **⌥↑** / **⌥↓**、元に戻す・やり直す、**⌘S** で保存、インストール済みのフォーマッタ（Prettier、google-java-format、ktlint、rustfmt、gofmt、Black）で整える **⇧⌥F** に対応します。

画像（PNG、JPEG、GIF、WebP）は収まるように縮小したプレビューで開きます。エージェントが変更したファイルは自動で読み直されます。**エディタで開く**はファイルを VS Code、Cursor、またはシステムのエディタへ渡します。ファイルは読み書きされるだけで、実行されることはありません。

### コードをたどる

Kotlin、Java、JavaScript、TypeScript、Python、HTML、CSS（Tailwind を含む）、Rust、Go で:

| | |
|---|---|
| **⌘P** | 名前でファイルへ移動。`@` でこのファイルのシンボル、`#` でプロジェクトのシンボル、`:` で行 |
| **F12** または **⌘-クリック** | カーソル下の名前の定義へ移動（**⌘** を押したまま名前に重ねると、移動せずに定義を表示）。import のパスの上ではそのファイルを開き、定義そのものの上では使用箇所を一覧 |
| **⇧F12** または **⌥F7** | プロジェクトでその名前を使うすべての箇所 |
| **F8** / **⇧F8** | ファイル内の次 / 前の問題へ移動し、メッセージを表示 |
| **⌃Space** | 入力補完（名前の入力中や `.` の後にも自動で開く。↩ か ⇥ で挿入、Esc で閉じる） |
| **F2** | カーソル下の名前を使われているすべての箇所で変更（言語サーバーがなければこのファイル内だけ） |
| **⌘.** | 言語サーバーがここで提案するクイックフィックスとリファクタリング（ガターの電球はその行に修正があるしるし） |
| **⇧⌘O** / **⌥⌘O** / **⌃G** | このファイルのシンボル / プロジェクトのシンボル / 行 |
| **⌃-** / **⌃⇧-** | 移動した場所を戻る・進む |

定義はプロジェクトのファイルから名前で探します（`.gitignore` に従い、依存関係とビルドのフォルダは除きます）。インストールは不要です。同じ名前の定義が複数あれば、近いものから全部表示します。

その言語の言語サーバーがインストールされていれば、エディタは言語サーバーに問い合わせます。正しい定義へ直接移動し、実際の使用箇所だけを表示し、**⌘** を押したまま名前に重ねると型やシグネチャも表示します。その言語のファイルを開くと自動で起動します。

| 言語 | 言語サーバー（`PATH` 上） |
|---|---|
| Rust | `rust-analyzer`（`rustup component add rust-analyzer`） |
| Go | `gopls` |
| TypeScript、JavaScript | プロジェクトまたはユーザーの TypeScript 7（`tsc`）、または `typescript-language-server` |
| Python | `pyright`（`pyright-langserver`）、`basedpyright` または `pylsp` |
| Java | `jdtls` |
| Kotlin | `kotlin-language-server` |

大きなプロジェクトをまだ読み込み中のときや、何も見つからなかったときは、上と同じく名前で探します。rust-analyzer はビルドスクリプトと proc macro を無効にして起動するため、プロジェクトを開いてもそのコードは実行されません。言語サーバーがプロジェクト自身のコードを実行する形で起動することはありません。プロジェクトの TypeScript はパッケージマネージャーで自分でインストールしたもの（git が `node_modules` を追跡していない）だけを使い、jdtls は Gradle のインポートを無効にして起動し、kotlin-language-server は読み込みにビルドの実行が必要なため Gradle・Maven プロジェクトでは起動しません。

言語サーバーは入力中に問題も知らせます。エラーは赤い波線、警告は黄色、情報は青で表示され、行番号とスクロールバーの印も同じ色になります。ポインタを重ねるとメッセージが表示されます。ステータスバーにはそのファイルのエラーと警告の数が出て、**F8** で次の問題へ移動します。rust-analyzer はプロジェクトをビルドせず（`cargo check` は無効）、見つけられる問題だけを知らせます。 言語サーバーが修正を持っている問題（**Add import from "./bad"** など）では、カーソル行のガターに電球が表示され、メッセージの下にも修正が並びます。**⌘.** でカーソルや選択範囲に使える修正とリファクタリングをすべて表示します。修正は開いているファイルを一度に変更するので **⌘Z** 一回で戻せ、開いていないファイルはそのまま保存されます。 問題のメッセージの下と **⌘.** の一覧の最後にある **AI で修正** を押すと、問題の場所と言語サーバーのメッセージが接続中のセッションに渡されます。 入力中は言語サーバーの補完候補がカーソルの下に表示され、別ファイルの名前を選ぶと import も追加されます。言語サーバーがなければファイル内の単語を候補にします。 関数呼び出しを入力している間は、行の上にシグネチャが表示され、入力中の引数が強調されます。 名前にポインタをしばらく重ねると型やシグネチャが表示され、ステータスバーのエラー数をクリックすると、開いているすべてのファイルの問題がコードと一緒に一覧で表示されます。

エディタ下部のステータスバーには、表示中のファイルの言語サーバーが出ます。未インストールなら **… をインストール** と表示され、クリックするとその言語サーバーの公式インストールコマンド（`rustup`、`go install`、`npm`、Homebrew）を新しいターミナルタブで実行します。コマンドに必要なツールがない場合は公式ページを開きます。**設定 → プロジェクト → 言語サーバー** で一覧を確認できます。Agentty の実行中にインストールしても自動でつながります。言語サーバーはこのコンピュータ上で動き、コードはどこにも送られません。

### コードの横でエージェントと作業する

エディタのバーの **セッションを接続** で、エージェントのターミナルがコードの右に付きます（端をドラッグして幅を変更）。既定はアクティブなタブのエージェントで、列から別のセッションを選べます。セッションが許可や回答を待っているとバーのチップに表示され、クリックするとセッションが表示されます。

- **コードを選択** すると **AI に指示**、**コピー**、**定義へ**、**使用箇所** のバーが出ます。**AI に指示**（または **⌘K**）に書いた指示は、ファイルと選択した行の範囲と一緒に接続中のセッションへ送られます。
- **エージェントの作業が見えます。** エージェントがファイルを変えると、変わった行が光ってから消え、カーソルの位置にエージェントの名前（`Claude-3f9a`）が出ます。Claude Code は書き込む直前の位置も示します。複数のセッションが同時に作業でき、セッションごとにカーソルとバーのチップが付きます。チップをクリックすると、そのファイルのその位置へ移動します。
- **追跡**（バーの目のアイコン）をオンにすると、エージェントが変えようとしているファイルがその位置で前面に出ます（開いていなければ開きます）。キーボードのフォーカスは奪わず、入力中は待ち、ターミナルを表示中は何もしません。見えている範囲の上や下で作業中のエージェントはその端に表示され、クリックするとそこへスクロールします。
- **AI に指示** した行は、エージェントが変更するまで印が付きます。**⌥↩** は質問だけを送ります（ファイルを変えないよう伝えます）。
- **エージェントの変更をレビュー。** 開いているファイルでエージェントが変えた箇所ごとに、ガターにエージェントの色のバーが、ファイルのタブに点が残ります。下のバーで変更を順に確認し、**元に戻す**（エージェントが触る前に戻して保存、⌘Z で取り消し可）、**保持**（印を消す）、**すべて保持** を選びます。**比較** は変更前の行と今の行を並べて表示し、バーの **変更 N** は開いているすべてのファイルの変更をコードと一緒に一覧にし、**⌥F5** / **⇧⌥F5** で次・前の変更へ移動します。同じ行をエージェントが再び変えると一つの変更にまとまります。
- **自分の編集は守られます。** 未保存の編集があるファイルにエージェントが書き込んでも、別の行なら自動でマージし、同じ行のときだけどうするか尋ねます。エージェントが上に行を足しても、カーソルと表示は読んでいたコードのままです。
- コードの上のバーにカーソルの位置（`ApiClient › save`）が表示され、クリックするとそこへ移動します。定義・使用箇所の一覧では、選んだ場所の前後のコードが横に表示されます。
