# 2026-09-18 세션연결 개선 · 탭을 분할로 합치기

상태: ⬜ 대기 · 🔧 진행 중 · ✅ 완료 · ⚠️ 부분 완료/제약

## 요청 요약

- 분할 화면에서 바로 세션을 연결해서 같이 일하게 하기 (세션연결 페이지까지 가지 않고)
- Claude는 **공식 세션 간 통신**을 쓰고, 다른 AI는 기존 컨텍스트 전달 방식으로
- 연결을 끊는 기능
- 탭이 여러 개일 때 탭을 창 안으로 드래그해서 **분할로 합치기**
- 목록에서 "탭 2 / 탭 3"으로는 어느 창인지 알기 어려우니 **창을 직접 클릭해서 고르기**

## 확인한 사실 (추측 아님)

- Claude Code 세션은 `~/.claude/sessions/<pid>.json`에 스스로 등록한다: `name`(다른 세션이 부르는 주소), `sessionId`, `cwd`, `pid`, `status`, `messagingSocketPath`.
- 세션 안에서 `ListAgents`로 같은 머신의 다른 Claude 세션이 보이고 `SendMessage`로 메시지를 보낸다. CLI 하위 명령이 아니라 세션 도구다.
- Agentty가 Claude 창을 띄울 때 `--session-id`를 주므로, 그 id로 레지스트리에서 이름을 정확히 찾을 수 있다.

## 구현

| 항목 | 내용 |
|---|---|
| 레지스트리 리더 | `claude::peer_sessions()` / `peer_session(session_id)` — 등록된 세션 목록·이름·상태 (bridge, 테스트 포함) |
| 연결 방식 분기 | 양쪽 모두 Agentty가 아는 Claude 세션이면 **직접 연결**(서로 SendMessage), 그 외에는 기존 **컨텍스트 전달**(한 번 공유 / 실시간 연결) |
| 직접 연결 | 양쪽 세션에 상대 이름과 폴더를 알려 주는 짧은 안내를 주입. 이후 대화는 Agentty를 거치지 않고 두 세션이 직접 주고받음 (전달·중계 없음) |
| 연결 해제 | 링크 제거 + 직접 연결이었으면 양쪽에 "이제 메시지를 보내지 마세요" 안내 주입. 패널 헤더에 **모두 연결 해제** 추가 |
| 창 헤더 버튼 | 연결이 없어도 다른 에이전트 창이 있으면 🔗 아이콘 표시 → 패널에서 바로 연결 |
| 창 직접 고르기 | 패널의 "창에서 직접 고르기" → 화면의 창들이 연결 대상이 되고(에이전트가 아닌 창은 흐리게 "에이전트 세션이 아님"), 탭을 바꿔 가며 고를 수 있음. 상단 안내 바에서 취소 |
| 탭 → 분할 | 탭을 창 안으로 끌면 좌/우/위/아래 드롭 영역이 나타나고, 놓은 방향으로 그 탭의 창(분할 구조 통째로)이 합쳐짐. `PaneNode::attach`로 서브트리를 그대로 삽입 |
| 잘못된 매칭 방지 | 같은 폴더에서 손으로 띄운 Claude 세션이 다른 창의 세션으로 잘못 잡히던 문제 수정(다른 창이 소유한 id면 무시) |
| 디버그 드라이버 | 합성 드래그가 메인 스레드를 막아 드롭 영역이 그려지지 않던 문제 수정(타이머 기반 press/drag-to/release) |

## 알아둘 점 / 제약

- 상대 세션의 권한 모드에 따라, 받은 메시지에 답할 때 사용자 승인이 필요할 수 있다(테스트 중 Claude가 직접 언급).
- 직접 연결은 Agentty가 띄운 Claude 창(세션 id를 아는 창)끼리만 자동 인식된다. 셸에서 손으로 띄운 Claude는 컨텍스트 전달로 동작.
- 직접 연결에는 "실시간 연결/다시 공유"가 없다(전달할 것이 없음). 패널에는 **직접 대화** 배지로 표시.
